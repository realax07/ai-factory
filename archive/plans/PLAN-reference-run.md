## Найдено эталоном и исправлено

1. `pm_bounds_check --sessions` считал повтор пары project/owner_pm по
   всему реестру, включая закрытые записи. Раннер ставит
   `owner_pm=package_runner` всем стадиям — finish любой dev-стадии после
   уже закрытой стадии того же проекта получал FAIL. Теперь — только живые
   незавершенные записи: из проверки выпадают только `closed`/`released`
   (неизвестный или пустой статус остается — fail-closed).
2. `role_zone_policy._pattern_lang_subset` отвергал glob-сегмент против
   того же glob-сегмента: зона ревьюера per_task
   `code-reviews/<pkg>/review-*.md` против политики
   `code-reviews/<id>/review-*.md` — ZONE_OUTSIDE_POLICY, парное ревью
   J64.13 на настоящих воротах не стартовало. Одинаковый сегмент теперь
   покрывает сам себя; расширение — по-прежнему отказ.

## Возврат ревью review-001 (2 blocker)

Первая версия правки 2 расширяла зоны: цикл не проверял, что sup кончился
(`code-reviews/*` проходил против `code-reviews/*/review-*.md`, у sa —
`openspec/changes/*`), литерал проходил против любого glob-сегмента sup.
Переписано: литерал против glob — fnmatchcase, конец sub — только при конце
sup, `**` sup поглощает остаток лишь хвостом (`**` в середине — отказ; это
закрывает и старый дефект main). Свойство держит перебор: все пары
паттернов из алфавита сегментов против оракула семантики зон — 0 расширений
(прежняя версия ветки — 21805 пар, main — 19169). Minor: pm_bounds — список
завершенных статусов вместо живых; заглушка подменяет вердикт только в
файлах своей стадии; дописывание ревью покрыто тестом; git config машины
изолирован (`GIT_CONFIG_GLOBAL`, `GIT_CONFIG_NOSYSTEM`).
