## Вердикт: approve

Дефект живого ekotov PR #231 закрыт точечно: IR-02 «новый сервис» теперь срабатывает только на каталог `services/<name>/`, отсутствовавший в дереве HEAD-before, а не на любой A-файл под `services/`. Все 4 оси фокуса проверены:

1. **Merge-base логика корректна.** `_head_before_files` берёт `merge-base(main|origin/main, HEAD)` → `ls-tree -r`. Для закоммиченного PR-диффа это честное «до PR»; для незакоммиченных изменений (дифф vs HEAD) дерево merge-base либо совпадает с HEAD (работа поверх main), либо старее (работа поверх ветки PR, где сервис уже закоммичен этим же PR) — во втором случае каталог считается «отсутствовавшим до» → консервативный DENY, что семантически верно: PR вводит сервис целиком. Деградация (не git / нет main / ошибка) → None → фильтр не применяется → прежнее консервативное поведение; пустое дерево `[]` читается осознанно (TC-027: всё «новое» → DENY). Ленивое вычисление с флагом `head_before_done` — один вызов даже при None, только для new_dir-правил. Пробный прогон на собственном диффе подтверждает целостность.
2. **IR-02 для реальных новых сервисов не ослаблен (кейс 025).** TC-J58-025 — настоящий git-репо (init/commit/branch, не мок): `services/catalog/` отсутствует в HEAD-before → 2×DENY с IR-02. Падение дерева в None → прежний DENY; нечитаемое дерево никогда не даёт молчание.
3. **Exists-guard IR-01 и статус-фильтры не задеты.** Блок `if head_files is not None and not _require_paths_exist(...)` и логика `req_status`/`st is not None` в diff не входят — сверено с кодом на HEAD. Регресс 885 passed (включая все прежние TC-J58-001..023) фиксирует отсутствие побочных эффектов.
4. **Префикс-ловушка закрыта.** `seg = m.group(0).rstrip("/")` + сравнение `hf.startswith(seg + "/")` — trailing-slash якорит сравнение на уровень каталога: `services/frontend/` не матчит `services/frontend-v2/...` и наоборот (проверено живой пробой обоих направлений). Для `^services/[^/]+/` group(0) всегда кончается `/`, так что seg не вырождается; для гипотетического паттерна без trailing slash (`^deploy`) сравнение `deploy/` даже точнее (файл `deploy.txt` не считается каталогом) — поведение в безопасную сторону. Важно: сверка идёт по полным путям файлов head_before, а не по именам каталогов, так что каталог существует ⇔ есть хоть один файл под ним.

TC-024 (новый файл в существующем сервисе → молчание) и TC-026 (правило без флага → прежнее поведение) закрывают обе стороны флага; описание new_dir в description impact_rules.json согласовано с кодом (включая консервативную ветку None).
