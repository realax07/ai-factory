## Проверка по осям ТЗ 04 (live-пробы)

### (1) Атомарность reservation — лок

- **Каталог-лок выбран правильно** (mkdir атомарен и устойчив к удержанию убитым процессом лучше O_EXCL-файла; снимается rmdir). `registry_write` — tmp в том же каталоге + `os.replace` (атомарный rename той же ФС), cleanup tmp при исключении корректен (try/except BaseException + unlink), хвостов нет (тест автора + проба P1).
- **Live-проба P1 (конкуренция):** 6 реальных процессов, одинаковая зона `src/**` → ровно 1 WIN, 5 `ZONE_CONFLICT`, в реестре 1 запись. Приемка ТЗ «ровно один успех» выполнена. Разные repo (`test_same_zone_different_repos_allowed`) и разные зоны — допускаются; `closed` не держит зону.
- **Дыра M3:** crash с локом = перманентный таймаут, см. таблицу.

### (2) Glob-семантика зон

- Посегментный fnmatch: `*` не переходит `/`, `**` — вложенность, `a/**/b` — ноль и более сегментов, префикс без метасимволов покрывает детей, канонизация `./`, `\`, ведущего `/`. Тесты автора покрывают вложенные пути и префиксные конфликты (TC-SCH-001).
- **Дыры M4 (FN на `**/x/**` vs префикс) и m10-рядом FP** — см. таблицу; сами `glob_matches` корректны на всех 10 исследованных парах — дефект именно в `zones_overlap`.

### (3) Идемпотентность

- Тот же id + идентичный payload (порядок paths не важен — sorted) → OK, записи не дублируются; иной payload → `DUPLICATE_PAYLOAD`; повтор после `finished` → OK `idempotent=True`, статус не resurrect (проба H), зона остается удерживаться до явного решения ПМ (статус finished ∈ ZONE_HOLDING — соответствует «повторный запуск требует явного решения ПМ»). Полное соответствие ТЗ.

### (4) Post-check границы

- `-uall`: untracked-файлы в проверке (подтверждено пробой), игнорируемые git-файлы не учитываются (семантика git, допустимо); удаленные файлы попадают в список; `SESSION.md` исключен как маркер; branch/toplevel/SESSION.md при заданном worktree проверяются; чужой cwd (repo вместо worktree) → WRONG_WORKTREE; check без reservation → отказ («не гарантирует права» — дословно ТЗ).
- **Дыры M1 (rename/net-diff эскейп) и M5 (in-repo symlink вне зоны)** — см. таблицу. Symlink-проверка работает для целей вне repo и broken-ссылок (пробы E2/E3).
- Ограничение «локальный запуск без песочницы не обещает физической изоляции» — ТЗ признает; проверяются git-пути, что соответствует декларации.

### (5) Reconcile

- Ничего не удаляет молча — подтверждено и тестами автора (TC-SCH-005, включая сквозной `test_nothing_deleted_silently`: запись, worktree, незакоммиченный файл, `git worktree list` целы), и чтением кода: `reconcile` пишет только transition-разметку, удалений записей/файлов нет. PID жив → needs_attention (проба с `os.getpid()`), мертвый+чистое дерево → stale, dirty → needs_attention. closed не трогается. Соответствие ТЗ полное.
- Но: разметка пишется через миграцию **без бэкапа** (M2).
