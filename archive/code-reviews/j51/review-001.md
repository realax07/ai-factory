## Проверено живыми пробами и прогоном (оси брифа)

- **Ось 1 (worktree в prepare):** `--create-worktree` при ALLOW создает реальный worktree через session_worktree.sh, путь в ALLOW-объекте и реестре (TC-001, реальный subprocess). Деградация: ветка уже checked out → exit 0, `WORKTREE_UNAVAILABLE` в `warnings` payload+record+stderr, `worktree: None`, работа в общем дереве (TC-002) — WARN, не FAIL. Новое поле `warnings` не ломает существующие структуры (полный регресс зеленый).
- **Ось 2 (ложных блоков нет):** легитимная последовательная пара «A завершилась → B стартует» проходит: статусы `finished`/`accepted`/`returned` вне `WORKTREE_ACTIVE_STATUSES` — проба с реальным энфорсером дала `None` (пропуск). Параллельные без разных деревьев (running без worktree; две в одном) → блок WORKTREE_MISSING; со своими деревьями → пропуск; `FLOW_ENFORCER_WORKTREE=0` реально выключает (TC-006). Самоблока нет: энфорсер гоняет prepare в `--dry-run` (без side effects), своей записи в реестре на момент ворот еще нет (проба: running-сессия со своим деревом + новая → пропуск). Считывающийся реестр нечитаем → WARNING `worktree_gate_unavailable`, не блок (fail-open только у вспомогательной проверки, сами ворота prepare fail-closed — TC-007).
- **Ось 3 (regress):** маппинг детерминированный и чужие домены не гоняет: frontend/→tests/web, backend/→tests/api, остальное (scripts/, plugins/, корень) → tests/; порядок по файлам без дублей (unit TC-010 + e2e TC-012/013/016). Артефакт append-only: повтор → regress-2.md, regress-1.md байт-в-байт не тронут (TC-014). Commit честный: `_git_head(repo)` на момент записи, в артефакте совпадает с реальным HEAD (TC-012). `--final` пишет только regress-final.md, нумерованных не создает, повтор перезаписывает идемпотентно (TC-015); нумерованные не засчитываются финальными (regex fullmatch `\d+` корректно игнорирует regress-final.md при подсчете номера). Пустой дифф → PASS без прогона с note (TC-017), не-git → exit 2 (TC-018).
- **Ось 5 (тесты — поведение, не моки):** 17 тестов на реальных git-репо (make_repo с полной фактурой Флоу 1), flowctl гоняется реальным subprocess; отказ worktree в TC-002 — настоящий (переиспользование checked-out ветки), не подделка. Единственный мок — `subprocess.run` внутри энфорсера (обход side-effect-prepare), при этом сам prepare покрыт реальными прогонами TC-001/002 — приемлемо. Полный регресс фабрики: **681 passed** (664 прежних + 17 новых), включая опечатку «СОСТОЛСЯ→СОСТОЯЛСЯ».

## Резюме

Реализация соответствует плану J51.1/J51.2 (создание worktree при ALLOW + деградация WARN; энфорсер-DENY для параллельных без разных деревьев; детерминированный regress с append-only артефактом и honest commit). Архитектурно чисто, обратной совместимости не ломает. Единственное препятствие для approve — отсутствующая валидация `--change` (замечание 1): явный пункт фокуса ревью «нет инъекций через change-id» не выполнен. Фикс локальный, после него повторное ревью не требуется сверх проверки оси 4.
