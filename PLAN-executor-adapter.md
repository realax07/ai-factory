# PLAN-executor-adapter: сменный исполнитель агентных стадий (J65.5 + J64.7)

**Флоу: 4** — обслуживание фабрики: ядро конвейера (раннер, вотчдог, реестр
ролей) с дельтой спеки deterministic-flow. ТЗ называет пакет Флоу 1;
решение Заказчика 2026-11-12 — «Флоу 4 + дельта спеки» (прецедент J66).

## Решения Заказчика (2026-11-12, дословно)

- «Флоу 4 + дельта спеки (Рекомендую)»;
- исполнители: «pi + hermes + stub (Рекомендую)» — claude-code и qwen
  следующим пакетом;
- манифест: «Префикс run (Рекомендую)» — `run: <исполнитель>:<роль>`;
- модели: «roles.json + манифест (Рекомендую)».

## Цель

Гарантии конвейера не зависят от исполнителя: все ворота (prepare,
резервация, сверка диффа, гейты, provenance) — в раннере вокруг вызова
исполнителя; новый исполнитель — один файл `scripts/executors/<имя>.py`
без правок flowctl/gate_runner/session_check; вотчдог видит обход для любого
исполнителя; модель и провайдер — из `agents/roles.json` и манифеста.

## Этапы

1. Дельта спеки deterministic-flow (3 ADDED), sdd, tasks — change
   `openspec/changes/executor-adapter/`.
2. `scripts/executors/`: интерфейс (`Executor`, реестр по имени модуля),
   `pi` (боевой: роль-пак, zone-guard, `--no-extensions`), `hermes` (ручная
   стоп-точка ПМ, активные делегации — async_delegations), `stub`
   (команда из env — эталонный прогон и доказательство «один файл»).
3. Раннер: `run: <исполнитель>:<роль>`; вид стадии `agent` / `manual`;
   вызов через интерфейс; журнал запусков `<state>/executor_runs.jsonl`.
4. `agents/roles.json`: `provider`/`model` у ролей с паками; манифест —
   ключи `provider`/`model` стадии; сверка settings.example.json паков.
5. Вотчдог: процесс исполнителя без живой резервации на его рабочий каталог
   — BYPASS (в том же канале, что обход делегаций Hermes).
6. Тесты, гайд манифеста, README flow-control; архивация change.

Сьют фабрики; эталонный прогон J65.10 — в том числе на исполнителе `stub:`.
