# BUG-AF-RECHECK-001: flow-enformer разрешает продуктовую dev-задачу без архитектурного ревью

- Источник: внешний ревью-комплект (ChatGPT re-review), передан Заказчиком 2026-10-13
- Версия: 2e5f090 (проверена), подтверждено чтением кода ПМ 2026-10-13
- Серьезность: major / приоритет P1
- Компоненты: J43/J43.1 flow-enforcer, J46 architecture gate

## Статус

- 2026-10-13: open (в работе, PR #106, ветка pipeline/bug-af-recheck)

## Суть

`prepare_command()` (plugins/flow-enforcer/enforcer.py:364) строит flowctl
prepare без `--path` → `ActionRequest.paths` пуст → `product_paths()` пуст →
`_arch_review_gate()` не применяется. Продуктовая dev-делегация проходит без
архитектурного approve даже в strict. Разрыв интеграции J43×J46: сам по себе
J46 при явном `--path` работает.

## Факт/ожидание

- Факт: prepare без --path → ALLOW; с --path → DENY ARCH_REVIEW_MISSING;
  hook не блокирует.
- Ожидание: контроль получает пути из структурированного входа (явный запрос
  или данные задачи/change-пакета); отсутствие путей ≠ docs-only. Docs-only
  сохраняет облегченный маршрут.

## Критерии исправления

- Интеграционный тест: hook + настоящий flowctl, продуктовая задача без
  arch-review → block + ARCH_REVIEW_MISSING.
- С актуальным approve — проходит; docs-only — проходит без arch-review.
- Пути из данных задачи не теряются при построении команды.
- Неизвестный тип задачи / отсутствие сведений о путях — явная обработка.
- Проверки зон/конфликтов работают с теми же переданными путями.
