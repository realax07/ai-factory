# BUG-AF-RECHECK-003: новый return не отменяет предыдущий approve

- Источник: внешний ревью-комплект (ChatGPT re-review), передан Заказчиком 2026-10-13
- Версия: 2e5f090; подтверждено чтением кода ПМ 2026-10-13
- Серьезность: major / приоритет P1
- Компоненты: flow_check.approved_review_tasks(), flow_transition.architecture_review_verdict()

## Статус

- 2026-10-13: open (в работе, PR #106, ветка pipeline/bug-af-recheck)

## Суть

Обе функции считают действующим историческое approve:
- `approved_review_tasks` (flow_check.py:123) отбирает ТОЛЬКО approve-файлы и
  берет последнюю итерацию среди них — поздний `return` в состоянии не участвует;
- `architecture_review_verdict` (flow_transition.py:402) возвращает True при
  ПЕРВОМ найденном approve (даже не последнем).

 approve → return должно означать «разрешения нет» до нового approve.

## Факт/ожидание

- Факт: review-001 approve + review-002 return → code-review: задача покрыта
  review-001; арх: ok=true.
- Ожидание: действует актуальная применимая итерация; последующий return
  отменяет старое разрешение. Разные задачи/версии — явная применимость,
  глобальной отмены пакета не требуется.

## Критерии исправления (обе функции)

- approve→return: недействительно; return→approve: действительно;
  approve→return→approve: последняя применимая итерация;
- return задачи 1.2 не отменяет approve независимой задачи 1.3;
- поддерживаемые схемы имен и review-mapping.json обрабатываются;
- неоднозначная/нечитаемая последняя итерация не подменяется молча старым approve;
- где есть provenance-проверка — связать действительность с версией результата.
