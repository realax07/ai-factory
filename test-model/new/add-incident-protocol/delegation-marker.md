## Классы эквивалентности

| Класс | Вход (incident_ref) | Кейс |
|---|---|---|
| S1-префикс | S1-prod-down | TC-DEC-001 |
| без префикса | prod-down | TC-DEC-002 |
| префикс вне allowlist / деформированный | S4-…, s1-…, S1prod-down, …-S1-… | TC-DEC-003 |
| severity в маркере ≠ классификации FR-1 | S3-… при фактическом S1 | TC-DEC-004 |

Границы (между «валидный префикс» и «нет префикса»): отсутствие дефиса (S1prod-down), нижний регистр (s1-), префикс не в начале (hotfix-S1-prod-down) — TC-DEC-003; следующий уровень allowlist (S4-) — TC-DEC-003/TC-SEV-004.

Негативные классы: TC-DEC-002, TC-DEC-003 — ожидаемая ошибка задана (MISSING_INPUT, DENY, exit 1). TC-DEC-004 — ожидаемое следствие: процессное нарушение FR-4 фиксируется в ревью.

Комбинации: N/A (один вход — строка incident_ref; пара «маркер × наличие файла» отработана в post-mortem-gate, TC-PMG-001…006).

## TC-DEC-001 — маркер S1 распознается

- **Источник:** FR-4 + Scenario «Маркер S1 распознается» + NFR-1 (Must)
- **Тип:** позитив

**Данные:** маркер делегации с `incident_ref=S1-prod-down`; test-model/incidents/ пуст.

**Шаги:**
1. Передать маркер в flow_transition (Флоу 3); вызвать действие emergency_stabilize, затем archive_change.

**Ожидаемый результат:** severity S1 извлечен из префикса (`^S[123]-` совпал; в ctx check-вызора incident_severity=S1 — не UNKNOWN и не «неклассифицирован»); задача требует post-mortem-ворота при архивации: archive_change → Finding MISSING_INPUT «post-mortem … не найден», DENY, exit 1.

## TC-DEC-002 — маркер без префикса: неклассифицирован

- **Источник:** FR-4 + Scenario «Инцидент без severity в маркере» + NFR-1 (UNKNOWN не разрешает архивацию) (Must)
- **Тип:** негатив

**Данные:** Флоу 3-задача, маркер с `incident_ref=prod-down` (префикса нет); test-model/incidents/ пуст.

**Шаги:**
1. Вызвать flow_transition: emergency_stabilize, затем archive_change (Флоу 3).

**Ожидаемый результат:** классификация отсутствует: emergency_stabilize → Finding MISSING_INPUT «инцидент неклассифицирован: incident_ref без severity-префикса S1-/S2-/S3-»; archive_change → тот же код причины, DENY, exit 1; архивация не разрешается (неклассифицированный не открывает ворота FR-3).

## TC-DEC-003 — границы формата префикса

- **Источник:** FR-4 + design D1 (регулярное выражение `^S[123]-`, машинная различимость префикса) (Must)
- **Тип:** граница/негатив

**Данные:** три маркера Флоу 3: (а) `incident_ref=s1-prod-down` (нижний регистр), (б) `incident_ref=S1prod-down` (без дефиса), (в) `incident_ref=hotfix-S1-prod-down` (префикс не в начале строки).

**Шаги:**
1. Для каждого из (а)–(в) вызвать flow_transition, действие emergency_stabilize (Флоу 3).

**Ожидаемый результат:** все три значения не совпадают с `^S[123]-` → инцидент трактуется как неклассифицированный; Finding MISSING_INPUT «инцидент неклассифицирован…», статус DENY, exit 1 для каждого. Регистр и позиция префикса значимы — допуск не делается.

## TC-DEC-004 — severity маркера противоречит классификации FR-1

- **Источник:** FR-4 («severity в incident_ref MUST совпадать с классификацией по FR-1») (Must)
- **Тип:** комбинация/негатив (процессный контроль)

**Данные:** инцидент фактически S1 (прод недоступен, все запросы 5xx), но в маркере `incident_ref=S3-footer-typos` — занижен; post-mortem отсутствует.

**Шаги:**
1. Исполнитель классифицирует инцидент по FR-1: прод недоступен → S1; фиксирует в таймлайне реакции фактический класс S1.
2. Сверить severity маркера с классификацией (ревью initial response / post-mortem).

**Ожидаемый результат:** зафиксировано нарушение FR-4 (несоответствие маркировки классификации) в ревью post-mortem; ворота остаются детерминированными по маркеру (NFR-1: archive_change видит S3 и post-mortem не требует — машинного DENY по факту инцидента нет), поэтому расхождение обязано быть отмечено в секции «## Action items» файла test-model/incidents/2026-10-15-S3-footer-typos.md (исправление маркера — новая запись, append-only).
