# Домен: initial response 0–15 минут (FR-2)

- **Change:** add-incident-protocol
- **Источники:** requirements.md FR-2 + spec.md «Requirement: Initial response 0–15 минут» (сценарии: Порядок действий соблюден; Разбор до стабилизации заблокирован)

## Классы эквивалентности

| Класс | Вход | Кейс |
|---|---|---|
| Завершение ≤ T+15, порядок соблюден | валидный | TC-IRS-001 |
| Завершение ровно T+15 (граница) | валидный край | TC-IRS-002 |
| Завершение > T+15 | невалидный | TC-IRS-003 |
| Разбор до стабилизации | невалидный порядок | TC-IRS-004 |

Негативные классы: TC-IRS-003 (превышение окна), TC-IRS-004 (нарушение порядка). У обоих ожидаемая ошибка задана (фиксация нарушения в таймлайне/ревью post-mortem) — «молчаливого негатива» нет.

Состояния: N/A (объект состояния — таймлайн; «повторный initial response» спекой не определен).

Комбинации: N/A (порядок — одна последовательность из 3 шагов; S1/S2 покрываются TC-SEV-001/002, единственный числовой параметр — длительность окна, отработан на границе).

## Техники, примененные к границе окна

Граница между классами «≤15 мин» / «>15 мин»: T+15:00 ровно и T+15:01.

---

## TC-IRS-001 — порядок (1)→(2)→(3), завершение внутри окна

- **Источник:** FR-2 + Scenario «Порядок действий соблюден» (Must)
- **Тип:** позитив

**Данные:** инцидент `incident_ref=S1-login-500` (эндпоинт login возвращает 500 на все авторизации), старт реакции T=10:00:00; стабилизация (rollback) 10:12:00, уведомление Заказчика 10:13:00, фиксация incident_ref 10:14:00.

**Шаги:**
1. Выполнить initial response в порядке: откат/стабилизация → уведомление Заказчика (что случилось / что делаем / ETA) → фиксация incident_ref.
2. Записать timestamps в test-model/incidents/2026-10-15-S1-login-500.md, секция «## Таймлайн».

**Ожидаемый результат:** в таймлайне timestamps идут в порядке стабилизация(10:12) → уведомление(10:13) → incident_ref(10:14); окончание initial response 10:14 ≤ T+15:00; раздел «## Root cause» начинается после записи о стабилизации. Проверяемо парсингом таймлайна: все 3 timestamps присутствуют, монотонны, last − start ≤ 15 мин.

## TC-IRS-002 — граница: ровно T+15:00 проходит

- **Источник:** FR-2 («MUST укладываться в 15 минут», «не позже T+15 мин») (Must)
- **Тип:** граница

**Данные:** инцидент `incident_ref=S2-search-slow`, старт T=12:00:00, окончание initial response (фиксация incident_ref) ровно 12:15:00.

**Шаги:**
1. Зафиксировать таймлайн: начало 12:00:00, окончание 12:15:00.

**Ожидаемый результат:** длительность = 15:00 — нарушение протокола НЕ фиксируется (порог включительный: «не позже T+15»); в post-mortem отметки о превышении нет.

## TC-IRS-003 — граница: T+15:01 — превышение

- **Источник:** FR-2 + Scenario «Порядок действий соблюден» (негатив по окну) (Must)
- **Тип:** негатив

**Данные:** инцидент `incident_ref=S2-search-slow`, старт T=12:00:00, окончание initial response 12:16:00 (16 мин).

**Шаги:**
1. Зафиксировать таймлайн с timestamps 12:00:00 → 12:16:00 в test-model/incidents/2026-10-15-S2-search-slow.md.

**Ожидаемый результат:** превышение порога выявляемо из артефакта: (окончание − начало) = 16 мин > 15 мин — в post-mortem/ревью фиксируется нарушение протокола (проверяемость порога через timestamps, не настенный контроль). Проверяемо: разность timestamps > 15 мин и запись о нарушении присутствует.

## TC-IRS-004 — разбор причин до стабилизации

- **Источник:** FR-2 + Scenario «Разбор до стабилизации заблокирован» (Must)
- **Тип:** негатив

**Данные:** инцидент `incident_ref=S1-prod-down`; прод не стабилизирован (5xx продолжаются); исполнитель в 10:05 (до стабилизации 10:20) начал заполнение раздела «## Root cause» в test-model/incidents/2026-10-15-S1-prod-down.md.

**Шаги:**
1. Начать разбор причин при нестабилизированном проде.
2. Провести ревью initial response по таймлайну.

**Ожидаемый результат:** в post-mortem/ревью зафиксировано нарушение протокола: запись о начале root cause (timestamp 10:05) предшествует записи о стабилизации (timestamp 10:20). Проверяемо: в таймлайне timestamp первой записи root cause < timestamp стабилизации и нарушение отмечено в разделе action items / ревью.
