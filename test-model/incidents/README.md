# test-model/incidents/ — хранилище post-mortem инцидентов Флоу 3 (J48)

Контракт каталога (design D4 пакета add-incident-protocol; requirements FR-3,
NFR-2):

- **Назначение:** post-mortem инцидентов Флоу 3 (хотфикс). Обязателен для
  S1/S2 — ворота архивации `check_archive_flow3` (scripts/flow_transition.py)
  блокируют архивацию Флоу 3-задачи без post-mortem (FR-3, DENY). Для S3
  post-mortem не требуется (протокол Флоу 3 не применяется, FR-1).
- **Именование:** `<YYYY-MM-DD>-<incident_ref>.md`, например
  `2026-10-15-S1-prod-down.md`. Корреляция с воротами — по подстроке
  incident_ref в имени файла (детерминированный файловый матч, NFR-1).
- **Обязательные секции** (проверяются воротами по заголовкам):
  `## Таймлайн` (с timestamps initial response — проверяемость порога
  0–15 минут, FR-2), `## Root cause`, `## Action items` (каждый пункт — в
  change-пакет или бэклог). Без обвинений (blameless).
- **Append-only (NFR-2):** существующие файлы НЕ удаляются и НЕ переписываются
  — только новые записи. Enforcement — конвенция для агентов + ревью;
  машинный контроль неизменяемости (git-history сторож) — вне среза J48
  (Won't-граница design D4).

Исторические записи переносятся дословно (ретроактивная severity-разметка
старых инцидентов не проводится — решение по ОВ-1, default «нет»).
