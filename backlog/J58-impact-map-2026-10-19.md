# J58 — Impact-карта: обязательный артефакт СА + механическая сверка diff↔карта

**Заявлено:** 2026-10-19. **Заявка Заказчика (дословно):** « impact анализ у нас участвовал
в процессе последних релизов? …Давай. И везде во флоу его добавь».

## Диагноз (экспертиза ПМ, 2026-10-19)
Формального шага impact-анализа во флоу нет; последствия ловятся gates'ами ПОСЛЕ
(regress-final, I3/I4, J50) или живьем. Три пропуска последних релизов:
(1) contracts/openapi.json не перегенерирован (weather) — regress FAIL, круг зря;
(2) static_v не забамплен (video-1.1) — девопс остановил деплой;
(3) deploy.sh не знает weather (weather-1) — вскрывось при деплое.
Каждое — минус цикл.

## Решение
1. **Impact-карта** — обязательный артефакт СА-пакета (openspec/changes/<id>/impact.md
   или секция design): затронутые сервисы / контракты / статика (static_v?) /
   deploy-матрица + RUNBOOK / миграции / тесты.
2. **Механическая сверка** (обобщение J50): pr_validate для [change-id] PR сверяет
   дифф с картой по правилам (extensible scripts/impact_rules.json):
   - `services/*/openapi*` или contracts/ → contracts/openapi.json в диффе
   - новая папка services/<name>/ → deploy/deploy.sh + deploy/RUNBOOK.md в диффе
   - frontend/ (static|templates) → static_v bump в backend/app/pages.py
   - migrate_*.py новый → RUNBOOK-упоминание миграции
   Расхождение = DENY с подсказкой.
3. **Флоу:** Ф1 — СА пишет карту, reviewers сверяют, pr_validate гейт; Ф2 — карта
   в fix-отчете (легче); Ф3 — impact в post-mortem; Ф4/5 — только механическая
   сверка правил (без карты) чтобы не душить chore.
4. **Промпты ролей:** СА (обязанность писать карту), code_reviewer (сверка),
   зеркала pr_validate/flowctl.

## Скоап
Фабрика: правила+гейт+тесты+доки (README-flow-control все флоу, agents/README,
factory_init шаблон change с impact-секцией). Зеркала: pr_validate/flowctl.
