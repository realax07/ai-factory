# J61 — package_runner: PI_ZONE_WRITE не прокидывается в pi (дефект пилота BUG-026)

**Статус:** ОТКРЫТ (заявлено 2026-11-02, пилот оркестратора BUG-026, 4 прогона)

## Факт
pi:dev (glm-5.3) получил корректный бриф и выполнил диагностику, но обе попытки
записи в свою зону `services/images/**` заблокированы zone-guard'ом («вне зоны»)
— guard работал на дефолтных зонах (tests/**). Причина: runner НЕ прокидывает
`PI_ZONE_WRITE` в env subprocess pi (grep по runner: env-передачи нет, только
упоминания в докстринге/ошибках). Диагностика pi: «обход через bash не делаю —
эскалация ПМ» (правильное поведение).

## Сопутствующие находки пилота (мелкие, одним фиксом)
- gate-команда обязана сужать скоуп сама (`--ignore=tests/web` без стенда ловит
  collection-error) — пример в гайде pipeline-manifest
- при STOP pi-вывод сохраняется (Д4 ✓), но WORKTREE reuse по session-id
  возвращает старую сцену (F16) — при resume с новой базой сносить сцену вручную
- runner перезаписывает AGENTS.md если pack-copy до Д3 (в main пострелизный — ок)

## Скоуп фикса (Флоу 4, S)
runner: env {**os.environ, PI_ZONE_WRITE: ':'.join(zones)} в subprocess.run pi;
негатив-тест: guard блокирует вне зоны / пропускает в зоне при env из runner.
