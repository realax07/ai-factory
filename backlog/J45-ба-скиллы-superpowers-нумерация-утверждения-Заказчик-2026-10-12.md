## Контекст (находки микроскопа)

1. Три адаптации obra/superpowers живут ВНЕ фабрики
   (`~/.hermes/skills/research/sp-*`) — не версионируются, не дистрибутируются.
2. Дубли: скилл requirements-elaboration повторяет контракт 1 по качеству
   требований — дрейф при первой правке.
3. Нет нумерационного реестра: «последние FR-106/NFR-29» БА узнает роясь в
   архиве вручную; r4/r5/r6 — отдельные файлы requirements-rN.md.
4. Не зафиксирован разбор утверждений Заказчика: «Утверждаю. + директива»
   (прецедент P15: «не забывай что нам макеты дизайна нужны» — стала
   обязательным ограничением пакета).
5. Разделение скилл/промпт (формула Заказчика): скилл = инструкции по задаче;
   системный промпт = мир роли (as-is, контракты, скиллы, окружение);
   best practice для всех ролей → системные промпты, для одной задачи → скилл.

## Задачи

1. **Перенос в фабрику** (skills/, без префикса sp-):
   - `brainstorming` (из sp-brainstorming): фаза ДО requirements-elaboration —
     пересказ понимания одной фразой, вопросы по намерению кластерами,
     ≥2 альтернативы с trade-off, anti-scope. В БА: первая фаза elicitation.
   - `writing-plans` (из sp-writing-plans): влить в openspec-authoring как
     раздел «декомпозиция tasks.md» (задачи-результаты, самодостаточность,
     критерии, порядок по зависимостям) — снять дубль с п.6.
   - `verification-before-completion`: НЕ скилл — абзац «Факты до заявления
     готовности» в системные промпты ВСЕХ ролей (общее поведение).
2. **requirements-elaboration**: убрать дубли контракта 1 (ссылка вместо
   повтора); добавить: (а) нумерационный преемник — «нумерация продолжает
   последний FR/NFR; источники: master-specs openspec/specs/ + архивные
   requirements (docs/ba, archive)»; (б) разбор утверждения — «УТВЕРЖДАЮ + текст»
   разбирается на директивы, каждая становится ограничением/требованием пакета;
   (в) жизненный цикл: requirements.md в корне = ТЗ активного пакета, при
   архивации — в docs/ba/requirements-<change>.md.
3. **agents/ba_agent.md**: таблица скиллов + brainstorming; зона записи
   уточняется «docs/ba/**» (история уходит при архивации); «разбор утверждений
   Заказчика» в границы роли.
4. **agents/README.md + все системные промпты ролей**: блок «Факты до
   заявления готовности» (sp-verification) — общий для всех.
5. **agents/README.md фабрики и ekotov-wiki**, test-case-design/case-review —
   без правок (уже J23-clean).
6. factory_init: ничего нового (skills/ копируется целиком — новые скиллы
   попадут автоматически; проверить).

## Критерий закрытия

- Скиллы brainstorming/writing-plans в skills/ фабрики, версионируются,
  уезжают factory_init'ом.
- requirements-elaboration: нумерационный преемник + разбор утверждений +
  жизненный цикл (без дублей контракта 1).
- verification-блок во всех промптах ролей.
- flow_check фабрики OK; references устаревших sp-* в agents/ — чисто.
