# J51 — Механизация параллельных делегаций: worktree в prepare + регресс-артефакт + ворота merge

**Флоу: 4** (заводской change-пакет: flowctl/flow_check/enforcer).
**Статус:** открыт. Источник: rich-редактор (add-rich-editor), день 2026-10-16 —
живая фактура деградации при параллельных агентах в общем worktree.

## Заявка Заказчика (дословно, 2026-10-16)

«Это же то, зачем я просил декомпозировать задачу. Каждому по его куску, а
финальный регресс всем скопом. Вопрос только как это контролировать.
На семантике — ты опять забудешь».

## Фактура (что случилось за день add-rich-editor)

1. **Параллельные dev/QA в одном worktree**: транзиентные фейлы тестов в момент
   чужих git-операций (ModuleNotFoundError flow_transition при pytest — дерево
   менялось под прогоном); сериальные ожидания финальных прогонов циклами
   process_manage по 3 минуты.
2. **Полный регресс (~10 мин) гонялся каждым агентом на своем шаге** — вместо
   «свой кусок → финальный скопом»: 4+ полных прогона за день.
3. **Жонглирование ветками ПМ** (архивация/сплиты): потерянный коммит-сплит
   (восстановлен из reflog), CI-прогоны по устаревшему payload, force-with-lease
   перезапись промежуточного пуша сабагента.
4. **Промпт-семантика не сработала**: сабагент запушил промежуточную (сломанную)
   версию вопреки «не пушить» — поймано верификацией ПМ, не механикой.

## Механика (предложение)

1. **Worktree в prepare**: flowctl prepare при ALLOW создает выделенный
   worktree (переиспользует session_worktree.sh) и возвращает путь в payload —
   каждый агент в своей копии дерева. Устраняет класс гонок структурно.
2. **`flowctl regress --change C`**: детерминированный маппинг диффа →
   затронутые тестовые домены (frontend → tests/web, backend → tests/api, и
   т.п.), прогон только их, запись артефакта
   `test-model/regress/<C>/regress-<N>.md` (PASS/FAIL + хвост лога).
   «Регресс своего куска» — каждому агенту механически.
3. **Ворота merge = regress-final**: check_change требует финальный артефакт
   `regress-final.md` (полный сериальный прогон, прогнан ПМ после approve всех
   ревью) — без него merge невозможен. «Финальный скопом» — железно.

## Критерии закрытия

- prepare создает worktree, путь в ALLOW-объекте; enforcer/доки обновлены
- flowctl regress работает на тестовом репо (маппинг диффа → домены)
- check_change: без regress-final → FAIL; regress-артефакты не считаются
  финальными (только regress-final.md)
- Прогнано на живом параллельном пакете (два агента, два worktree, ноль гонок)
