# J51 — Механизация параллельных делегаций: worktree в prepare + регресс-артефакт + ворота merge

**Флоу: 4** (заводской change-пакет: flowctl/flow_check/enforcer).
**Статус:** открыт. Источник: rich-редактор (add-rich-editor), день 2026-10-16 —
живая фактура деградации при параллельных агентах в общем worktree.

## Заявка Заказчика (дословно, 2026-10-16)

«Это же то, зачем я просил декомпозировать задачу. Каждому по его куску, а
финальный регресс всем скопом. Вопрос только как это контролировать.
На семантике — ты опять забудешь».

## Фактура (что случилось за день add-rich-editor)

1. **Параллельные dev/QA в одном worktree**: транзиентные фейлы тестов в момент
   чужих git-операций (ModuleNotFoundError flow_transition при pytest — дерево
   менялось под прогоном); сериальные ожидания финальных прогонов циклами
   process_manage по 3 минуты.
2. **Полный регресс (~10 мин) гонялся каждым агентом на своем шаге** — вместо
   «свой кусок → финальный скопом»: 4+ полных прогона за день.
3. **Жонглирование ветками ПМ** (архивация/сплиты): потерянный коммит-сплит
   (восстановлен из reflog), CI-прогоны по устаревшему payload, force-with-lease
   перезапись промежуточного пуша сабагента.
4. **Промпт-семантика не сработала**: сабагент запушил промежуточную (сломанную)
   версию вопреки «не пушить» — поймано верификацией ПМ, не механикой.

## Механика (предложение)

1. **Worktree в prepare**: flowctl prepare при ALLOW создает выделенный
   worktree (переиспользует session_worktree.sh) и возвращает путь в payload —
   каждый агент в своей копии дерева. Устраняет класс гонок структурно.
2. **`flowctl regress --change C`**: детерминированный маппинг диффа →
   затронутые тестовые домены (frontend → tests/web, backend → tests/api, и
   т.п.), прогон только их, запись артефакта
   `test-model/regress/<C>/regress-<N>.md` (PASS/FAIL + хвост лога).
   «Регресс своего куска» — каждому агенту механически.
3. **Ворота merge = regress-final**: check_change требует финальный артефакт
   `regress-final.md` (полный сериальный прогон после approve всех ревью) —
   без него merge невозможен. «Финальный скопом» — железно.

**Решение Заказчика (разбор инцидента 2026-10-16): regress-final исполняет
САБАГЕНТ, не ПМ** (ПМ — не исполнитель). Роль: новая (рабоче название
regress_runner) или переиспользование qa_runner (J17-2) — решить при
реализации. ПМ принимает артефакт (вердикт + provenance), не запускает прогон.

**Профиль роли (уточнение Заказчика):** регрессу не нужен контекст релиза —
узкий бриф: ветка, коммит, затронутые сьюты. Обязанности: запуск → различение
бага от флака (изолированный перепрогон упавших) → вердикт; FAIL (не флак) →
возврат dev'у на доработку. Дешевый, быстрый, независимый — сознательно без
контекста релиза.

## Критерии закрытия

- prepare создает worktree, путь в ALLOW-объекте; enforcer/доки обновлены
- flowctl regress работает на тестовом репо (маппинг диффа → домены)
- check_change: без regress-final → FAIL; regress-артефакты не считаются
  финальными (только regress-final.md)
- Прогнано на живом параллельном пакете (два агента, два worktree, ноль гонок)

## Швы, вскрытые пилотом (→ J52)

1. Ветки деривятся из первых 8 символов correlation-id → коллизии префиксов
   (j51-pilot-A/B дали одну ветку flow/j51-pilo). Фикс: полный id или хэш-суффикс.
2. regress_runner не имеет действия в графе Флоу 4 (chore_task = dev) — роль
   запускается как dev; решить: action regress_task или политика.
3. needs_attention-сессии держат зоны; явного «сброса ПМ» нет (reconcile не
   освобождает) — нужен документированный выход.
4. adapter=manual: пропущенный flowctl run между prepare и finish делает
   finish невозможным, повторный run после факта → STALE_SNAPSHOT («повтори
   prepare») — задокументировать порядок prepare→run→делегация→finish.
5. Гранулярность доменов regress — правило Заказчика (2026-10-18): домены
   такие же, как в тест-кейсах — единая структура «кейс ↔ домен»:
   approved-кейсы группируются по доменам, маппинг диффа резонирует с этой
   структурой, а не с техническими путями tests/api|web. Детализация — при
   реализации.

## Швы раундов regress-final (2026-10-18, → J52 дополнение)

6. **Зеркало диффом без зависимостей**: sync одного скрипта (flowctl.py) без
   его зависимостей (session_check.change_id_problem, pr_validate.
   check_regress_final) → AttributeError на первом же прогоне. Правило:
   зеркало скрипта = зеркало его импорт-замкнутости (список зависимостей
   в фабрике, проверка flow_check на проекте).
7. **Ворота regress-final вскрывают грязь main**: pre-existing фейлы main
   блокируют merge релиза. Нужен baseline-механизм (список известных
   фон-фейлов в артефакте) ИЛИ правило «гигиена main — часть релизной
   волны 0». Решение при реализации J52.
8. **Голый `from conftest import`** в tests/* — ломает полную коллекцию
   (sys.modules['conftest'] затирается tests/web/conftest). Правило в
   qa_automation/test-automation: импорты хелперов тестов — через пакет/фикстуры.

## Класс «обкатка ворот» — превентивные меры (поручение Заказчика 2026-10-18)

Первое применение ворот J51 на video-hosting вскрыло 4 фабричных бага
(BUG-005/022/023/024) + 2 пропуска контрактов. Класс один: **ворота
тестируются в комфортной среде автора, а работают в CI-среде**.

Превентивные меры (реализовать в пакете J52):
1. **Gate self-test harness** — CI-имитация для любых ворот: shallow-клон,
   отсутствие локальных путей, API-моки. Ни одни ворота не вливаются без
   прогона в harness (лечит класс BUG-022/023/024 до merge).
2. **Контракт 6/7 в промпт dev** (тест-багфикс): репорт BUG-NNN — часть
   коммита, не воспоминание. Плюс: pr_validate в ошибке печатает
   remediation-подсказку (путь репорта + шаблон «Статус»).
3. **Машиночитаемый формат мет ревью** — зафиксировать в скилле
   code_reviewer (строка Reviewer-Delegation: deleg_<id> вплотную);
   flow_check при непокрытии печатает remediation (какой файл, какой
   формат, какая задача).
4. **Зеркало с замкнутостью импортов** (уже в J52 п.6): sync-команда
   резолвит импорты копируемого скрипта и тянет их рекурсивно.
5. **Freeze tooling перед regress-final** (уже в J54) — фиксирует класс
   «мета-коммит после артефакта = перегон» до введения исключений.

6. **Контракты — в промпты ролей, не в голову ПМ** (корневой вывод разбора
   2026-10-18, подтвержден Заказчиком): конфликты знаний ПМ↔сабагенты —
   главный источник кругов. Стоячие контракты вшиваются в системные промпты:
   dev — «репорт BUG-NNN = часть коммита; ветка/worktree из ALLOW»,
   code_reviewer — точный машиночитаемый формат review-файла
   (Вердикт: approve + Reviewer-Delegation: deleg_<id> вплотную),
   regress_runner — freeze tooling. ПМ перестает быть носителем контрактов.
