## Решения Заказчика 2026-10-09 (по пунктам)

### (1) Required checks — ПРИНЯТЬ (ruleset активен в обоих репо)

Факты 2026-10-09: фабрика — ruleset `main` active, required check `test-flow-control` (PR + non_fast_forward). wiki — ruleset `main` active, но required checks ПУСТОЙ. Действие ПМ: добавить в wiki ruleset required checks `flow` + `e2e` (API-вызов). После этого красный flow блокирует merge в обоих репозиториях (случай PR #28 не повторится).

### (2) Reviewer-Delegation id — оставить текущую практику

Рабочая практика P14 (4 раза отработана): ТЗ ревьюеру говорит «мету поставит ПМ»; ПМ вписывает платформенный id при влите review-файла. Автоматизация (delegate_gate выдает id при диспатче) — в J35-класс при касании delegate_gate. Не блокирует.

### (3) review-mapping.json автозаполнение — отложить в J35-класс

Требует правки delegate_gate (дописывать mapping при approve ревьюера). Частота ручной строки — раз за review. В бэклоге, приоритет низкий.

### (4) Файловые тесты и стенд — ОТКАЗ от ленивой фикстуры (риск симуляции)

Решение Заказчика: оставить как есть. Разбор: файловые тесты (test_search_contract_is_frozen и т.п.) проверяют статические артефакты — «реальности» не теряют; но падение сборки без стенда — полезный сигнал E6 («подними стенд»). Ленивая фикстура размыла бы сигнал: «тесты зеленые, но половина реально не проверялась» = симуляция вместо реальной проверки. Профит (60 сек подъема в редких прогонах) несоизмеримо меньше риска. Тест migration* используют собственную tmp-БД (стенд не нужен и не требуется).

### (5) «Что проверяется когда» — ДОБАВИТЬ в docs/ci-gates.md (ПМ, 2026-10-09)

Раздел: flow_check — на каждом PR (промежуточные стадии Флоу 1 и финальные); pr_validate (полный QA-хвост) — только change-маркерные PR финальной стадии. См. этот PR.

### (6) PR_CHANGED env-конвенция — РЕАЛИЗОВАНО (закрыть)

Пункт сформулирован по неполным данным: flow.yml уже вычисляет дифф через git diff --name-only (subprocess-эквивалент), env лишь передает результат в pr_validate. «Честность CI-скрипта» = сам скрипт считает дифф; риска подмены env вручную на штатном CI нет (env выставляется в том же run-блоке). Закрыто как реализованное.
