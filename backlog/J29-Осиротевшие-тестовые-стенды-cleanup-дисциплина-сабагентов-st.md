# J29: Осиротевшие тестовые стенды: cleanup-дисциплина сабагентов + stand_reaper (выявлено 2026-10-01).

- **Статус:** ОТКРЫТО
- **Карта:** backlog/MAP.md (строка item'а)

Факт: на машине скопилось 8 осиротевших uvicorn/http.server (26ч/12ч/8ч, ~970 MB RAM из 4GB): (а) стенд ПМ после верификации багфикса Р4 (не погасил после merge); (б) стенды dev 3.1 Р5 (r5-card) — сессия оборвана по max_iterations ДО cleanup-фазы, worktree удален, процессы остались; (в) контрольный прогон 4.3 ПМ. Правило (дополнение J24/J20): **dev/qa-сабагент в cleanup-фазе обязан гасить поднятые им процессы (pkill по cwd своего worktree); ПМ при приемке делегации проверяет сироты** (ps + /proc/PID/cwd указывает на несуществующий worktree → убить). Кандидат в детерминированный слой (J28): `scripts/stand_reaper.py` — реестр живых стендов (uvicorn/http.server с cwd в ekotov-wiki*), kill тех, чей cwd не существует или не в активных worktrees; запуск cron/по приёмке. Связь: J28 (детерминизация), J24 (предыдущий случай stale-стендов), J26 (devops).
