# J7: Физическая защита worktree-изоляции при параллельных делегациях (инцидент Релиза 3, 2026-09-27).

- **Статус:** ЗАКРЫТО (принятый риск платформы, 2026-10-10)
- **Карта:** backlog/MAP.md (строка item'а)

Факт: 2 из 4 параллельных dev-сабагентов в какой-то момент работали в ЧУЖИХ worktree (поменяли местами r3-profile и r3-forms) — незакоммиченные правки оказались в чужих деревьях, дублируя собственные коммиты. Пострадавших нет (коммиты легли верно, ПМ сверил диффы байт-в-байт и зачистил мусор), но изоляция E5 не спасла: правило 11 дает каждому свое место, но не предотвращает ошибку каталога. Корень: путь worktree передается текстом в goal — при 4+ параллельных сабагентах модель путает собственный cwd и целевой worktree. Направления решения (нужен выбор): (а) физическое — у сабагента НЕТ доступа к соседним деревьям (запуск из изолированного cwd, контейнер, права ФС по пути); (б) полупрограммное — worktree-boundary check в dev_agent.md: первый шаг сессии — pwd + git rev-parse --show-toplevel + git branch --show-current, сверить с ТЗ, не совпало → стоп-эскалация; (в) маркер в дереве — ПМ кладет в корень worktree SESSION.md (id, ветка, задача), сабагент сверяет первым действием; (г) метка в goal: первый tool-вызов — проверка пути, зафиксировать в отчете. Связь: E5, правило 11. Верификация решения — негативный прогон: сабагенту дают чужой worktree, он обязан остановиться.


**ЗАКРЫТО 2026-10-10 (решение Заказчика):** корень инцидента — платформа Hermes
(роутинг сессий/rollover), не конвейер. Настройки платформы выполнены (сессии,
watchdog, дисциплина сабагентов); отвалы будут, но приемлемы. Заказчик будет
регулярно обновлять платформу — свежие версии могут закрыть корень. При рецидиве —
переоткрыть с новым фактом.
