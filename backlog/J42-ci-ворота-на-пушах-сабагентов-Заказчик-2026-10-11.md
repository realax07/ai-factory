# J42 — CI-ворота на пушах сабагентских веток (Заказчик, 2026-10-11)

**Флоу: 4** (обслуживание — расширение CI-контура фабрики и проектов). Источник:
диалог 2026-10-11 по итогам J41. Статус: открыт. РЕШЕНИЕ Заказчика (2026-10-18): слоистая организация —
L1 ruleset main bypass-never (есть) + L2 CI-триггер pipeline/** (J42-B) +
L4 enforcer-перехват git push (ветка из ALLOW; в пакет J52), L3 bot-identity —
отдельное заводское решение, не в скоупе.

## Проблема

Сабагент коммитит локально, пушит ПМ; flow_check гоняется только на PR и на
main. Голый пуш сабагентской ветки `pipeline/**` CI не триггерит — пропущенные
этапы видны ПМ только при приемке или открытии PR.

## Идея Заказчика (дословно)

«С той точки зрения, что гит даст знать, если предыдущие этапы пропущены,
сразу на уровне сабагента, и он вернет ошибку ПМ».

## Уточнение механики (разбор с Заказчиком, 2026-10-11)

Git сам этапы не знает — проверки несет flow_check (CI-job). Required checks
привязаны к PR в защищенную ветку, не к голому пушу ветки. Рабочие варианты:

- **A (минимальный):** правило «сабагент завершается PR'ом» — flow_check
  гоняется на PR сабагента автоматически, красный = ошибка ПМ. Ноль кода.
- **B (строже):** добавить в flow.yml триггер `push: branches: ["pipeline/**"]`
  (+ шаг auto-`gh pr create`/комментарий) — сабагентский пуш без этапов
  краснеет в самой ветке, уведомление ПМ.

## Задачи

- [ ] Фабрика: вариант B — триггер `pipeline/**` в flow.yml + поведение
      (auto-PR или падающий job с ::error::).
- [ ] Проекты (ekotov-wiki и далее): та же правка flow.yml (тонкий клиент).
- [ ] AGENTS.md обеих реп: правило «сабагент завершается PR'ом (A) / пушит в
      pipeline/** (B)»; push-политика п.4 пересматривается по итогам.
- [ ] Решить замечание о credеншалах: сабагент и ПМ делят git-креденшал —
      технического разделения нет (deploy-ключи — отдельный кандидат при
      необходимости).

## Критерий закрытия

Пуш сабагентской ветки с пропущенным этапом краснеет в CI до приемки ПМ;
ПМ получает уведомление (check-fail / комментарий).
