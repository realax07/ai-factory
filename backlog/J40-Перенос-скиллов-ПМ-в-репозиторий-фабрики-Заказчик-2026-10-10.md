# J40: Перенос скиллов ПМ (Hermes-скиллы) в репозиторий фабрики

- **Статус:** ОТКРЫТО
- **Карта:** backlog/MAP.md (добавить строку)

## Предмет (поручение Заказчика 2026-10-10)

Персональные Hermes-скиллы ПМ (`~/.hermes/skills/devops/*`, категория
ai-factory/ekotov) содержат проверенные процедуры конвейера, но живут вне
репозитория — не версионируются фабрикой, не проходят PR-процесс, недоступны
другим агентам/машинам. Знание должно жить в репо (правило «передача — только
артефактами в репозитории»).

## Инвентаризация источника (12 скиллов)

Относятся к фабрике/ekotov (перенести):

## Порядок переноса

1. Для каждого скилла: копия в `skills/<name>/` фабрики, адаптация путей
   (~/.hermes → относительные/репо), дедупликация с существующими
   (factory-flow уже покрывает часть flow-control — слить, не дублировать).
2. README.md каталога skills/ — индекс с назначением каждого.
3. Ссылки из agents/*.md промптов — где роль использует скилл (например
   sa_agent.md → flow-playbooks: нарезка обязана включать QA-контур, J39).
4. Верификация: свежий клон фабрики — скиллы находятся, ссылки не битые.
5. После переноса — исходники в ~/.hermes/skills/devops/ пометить
   «каноничный источник — репо фабрики» (симметрично двусторонней
   синхронизации ядра), не удалять без решения Заказчика.
