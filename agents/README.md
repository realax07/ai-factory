# Реестр агентов конвейера

Каждый файл в этой папке — исполняемая инструкция для одного сабагента. Инструкция самодостаточна: подается агенту как системный промпт вместе с задачей.

## Конвенции

- **Именование:** `{роль}_{функция}_agent.md`, строчными буквами, латиницей.
- **Единый шаблон инструкции:** Роль и границы → Триггер → Вход → Выход → Правила → Чеклист самовалидации → Эскалация.
- **Один агент = одна ответственность.** Валидация результата — всегда отдельный агент или отдельная итерация, никогда не самопровокация автора.
- **Передача работы — только через артефакты** (файлы в репозитории проекта), не через контекст диалога.
- **Статусы:** `активен` (в конвейере пилота), `резерв` (готов, не задействован), `черновик` (инструкция не выверена).

## Поток конвейера (этапы)

```
Заказчик → Бизнес-анализ → Системный анализ → Разработка → Тестирование → Внедрение
```

Для пилотного проекта (ekotov-wiki) этап бизнес-анализа схлопнут в один шаг: требования фиксирует агент-ПМ, валидирует заказчик (см. PLAN.md, раздел «Решения»). Оба агента-БА — в резерве для последующих проектов.

## Планируемые роли (не написаны)

- Системный аналитик: `requirements_detailed.md` → SDD (архитектура, стек, контракты API)
- Архитектор-валидатор: проверка SDD на полноту и реализуемость
- Разработчик: SDD → код + тесты в репозитории проекта
- Код-ревьюер: валидация кода против SDD и чеклиста качества
- QA-инженер: приемочные проверки по критериям из требований
- Release-инженер: сборка, развертывание, проверка окружения
