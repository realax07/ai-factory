### m8 (minor, на решение Заказчика): исключение для пакетов обслуживания фабрики записано без артефакта решения

Где: `docs/guides/external-orchestrator.md:67-71`, `PLAN-executor-swap-skill.md:42-49`.

С п.21 противоречия нет: работа идет через PR, ревью обязательно, ревьюер
отдельный, независимость соблюдена (самоприемки нет). С разделом
«Оркестрация» AGENTS.md есть напряжение. Правило «Ревью засчитывай только с
provenance (`gate_runner record-review` …)» помечено (ПМ). Гайд же описывает
ситуацию, где внешний агент сам и есть оркестратор-ПМ. Исключение снимает
provenance и переносит приемку на Заказчика при merge. Опора на прецедент
(«как пакеты J64/J65»; например, в `code-reviews/executor-adapter/` sidecar
provenance тоже нет) фактически верна. Но в `decisions/` нет решения,
которое закрепляло бы эту практику как правило, а по п.5 и п.18 исключение
из правила фиксирует Заказчик артефактом. Кроме того, «отдельный агент» в
исключении на практике и есть сабагент оркестратора, которого предыдущий
пункт (`:61-66`) запрещает. Различие держится только на типе пакета.

Что сделать (не блокирует, так как merge все равно по слову Заказчика):
Заказчику при merge подтвердить практику записью в `decisions/` (или
approval_ref), а гайду сослаться на нее. Другой вариант — добавить к ревью
пакета sidecar `gate_runner record-review` с id сессий автора и ревьюера.
