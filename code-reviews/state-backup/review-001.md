## Проверено, замечаний нет

- Атомарность публикации backup: запись в `.part` + `rename` в том же каталоге; `--dest` внутри state — отказ (resolve, включая сам state).
- Исключение `session-archive/`: `_filter` возвращает None для каталога — tarfile не рекурсирует; ссылки/устройства отбрасываются.
- restore: проверка путей (абсолютные, `..`, вне `state/`), типов (только file/dir — hardlink/symlink/fifo отклоняются), `filter="data"` на 3.12+; staging рядом с state (тот же FS, rename атомарен); прежний state не удаляется.
- Крон: обертка `CRON_WRAPPER_TEMPLATE` пробрасывает `sys.argv[1:]` — `state_backup.py backup` работает; успех — пустой stdout; без подкоманды — argparse exit 2. Exit-коды соответствуют докстрингу.
- factory_paths: `backup_dir()`/`describe()`/`DOCTOR_ENV` — аддитивно; энфорсер `backup_dir` не использует, паритет-тест зеленый. factory_init: добавление в `WATCHDOG_SCRIPTS` и строка таблицы не ломают install_crons (тест TC-J64-SB-005), таблица синхронна с docs/README-flow-control.md.
- RUNBOOK согласован с bootstrap: bootstrap создает state с `flow_mode.json=shadow`, restore (с `--force` или без — активных сессий там нет) откладывает его; повторный bootstrap без `--flow-mode` восстановленный enforcing не трогает (factory_bootstrap.py:137-144).
- Прогон: затронутые модули — 41 passed, 1 skipped.
