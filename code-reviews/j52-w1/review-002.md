## Major-1 (release TOCTOU) — ЗАКРЫТ

- `registry_transition(..., expect_from=...)`: фактический статус сверяется **после** `_acquire_lock` и **до** `sc.transition` — не совпало → `{"ok": False, "reason": "status_changed", "current_status": ...}`, реестр не пишется. Именно та точка, которую требовало review-001: окно «чтение prev без лока → переход» больше не проходит мимо валидации.
- `cmd_release` передает `expect_from=prev`; в отказной ветке — exit 1, `refused: true`, `status_now`, note «статус изменился, повтори release … сессия НЕ тронута».
- **TC-J52-017** (прогнан): гонка смоделирована monkeypatch `sc.registry_load` — конкурентный процесс пишет reserved→running между первым чтением и захватом лока → release отказывает (rc=1), **running сохранен** в реестре, state не тронут (prepared), audit-событий release нет. Юнит-кейс: expect_from-mismatch → status_changed, статус не тронут; match → переход выполняется.
- Идемпотентность не пострадала: сценарий «released между чтением и локом» дает честный status_changed → повтор → no-op exit 0 (проверено по коду: ранний выход на `prev=="released"` до лока безопасен — ложный no-op невозможен, т.к. prev читается из того же снимка, а несовпадение под локом отсекается).
