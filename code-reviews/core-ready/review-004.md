## Находки

### n4 (nit): change-id Флоу 1 вида `bug-042` совпадает с bug-id Флоу 2 со slug

`scripts/pr_validate.py:345-347`. Строчный fallback в `bug_base` превращает change-id Флоу 1 `bug-042` (он
валиден по `CHANGE_ID_PATTERN`) в `BUG-042`. Поэтому `scope_matches("BUG-042-fix", "bug-042")` дает True:
ревью бага BUG-042 засчитается для change-пакета `bug-042`. Без slug это было и раньше (`bug-042` == `BUG-042`
без учета регистра). Для обхода нужны одновременно change-id `bug-NNN` и баг с тем же номером, а
`runner_review_ok` к тому же сверяет конкретную делегацию из review-файла. Риск минимальный. Если закрывать —
передавать флоу явно (флаг `bug=True` только из цепочки Флоу 2), как в варианте 1 из review-003.

### n5 (nit): строчный каталог фабрики со slug (`bug-026-fix`) больше не находится

`scripts/pr_validate.py:76, 345-347`. В d59e19a `bug_review_dir(repo, "026")` находил `code-reviews/bug-026-fix/`
по строчному префиксу. Теперь строчная форма принимается только без slug: `bug-026-fix` → `None`, и ворота дают
«нет review-файла». Это отказ, а не пропуск, и сейчас в фабрике каталоги без slug (`bug-025`, `bug-026`).
Достаточно зафиксировать соглашение «каталог ревью бага фабрики — `bug-NNN` без slug» или принять строчный slug
явно, если он понадобится.

### n6 (nit): `bug_review_dir` не ставит точное имя первым при разном регистре

`scripts/pr_validate.py:75-77`. `sorted` сортирует по коду символа. При одновременных `BUG-026-fix/` и `bug-026/`
первым станет `BUG-026-fix`. Для `BUG-042` и `BUG-042-fix` порядок верный: точное имя короче. Случай искусственный,
не блокирует. Если править — ключ сортировки `(d.name.upper() != want, d.name)`.

### Вне диффа (для backlog)

`scripts/flow_check.py:61-62`, `bug_report_paths`: glob `BUG-{digits}-*.md` имеет ту же склейку, что и m11.
Для `BUG-042` подойдет `BUG-042-RECHECK-003.md`, если нет точного `BUG-042.md`. Влияние малое: `check_bug`
читает только раздел «Статус» репорта. Это код до пакета, на вердикт не влияет. Стоит завести item на
выравнивание с `bug_base`.
