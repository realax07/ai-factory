  маркер можно, но комментарий «регресс обязателен отдельным шагом» создает
  впечатление дополнительной защиты, которой нет.

### 5. Поймал бы harness класс BUG-022/023/024 на старых версиях? Прогон

Вердикт эксперимента (реальные прогоны harness-кейсов на пре-фиксных
версиях scripts/pr_validate.py, HEAD-версии остальных скриптов):

| Версия pr_validate | Прогон TC-030/032/033 | Ловит? |
|---|---|---|
| 6473ad8 (до фикса BUG-022) | TC-030 **FAIL** — ложный REGRESS_FINAL_STALE в shallow-клоне | **ДА** |
| 596d262~1 (BUG-023 присутствует) | 3/3 passed | **НЕТ** |
| 12496ec~1 (BUG-024 присутствует) | 3/3 passed | **НЕТ** |

Причина по коду: в `make_origin` все коммиты (change-пакет h1 → regress-final
h2, негативные правки) создаются в пределах одной секунды; fresh-сверка
`_regress_commit_problem` сравнивает `int(ts) > int(art_ts)` — секундная
гранулярность схлопывает все сравнения в равенство, fresh-ось полностью
нейтрализована. TC-032 (stale) проходит по ancestry-ветке (чужой commit),
fresh-ветка ворот не покрыта ни одним кейсом. Следствие: регрессия фикса
BUG-023/024 (удаление исключений мета-путей) harness сегодня НЕ поймает.

Контроль-эксперимент: те же версии с разнесенными датами коммитов
(GIT_AUTHOR_DATE/GIT_COMMITTER_DATE, шаг 60с) + пост-артефактный коммит:

- пре-фикс 596d262~1 + мета-коммит code-reviews/** после regress-final →
  ложный STALE (ровно BUG-023/024);
- HEAD + тот же мета-коммит → PASS (exit 0);
- HEAD + пост-артефактный **продуктовый** коммит tests/** → STALE (exit 1).

То есть добавление датированных коммитов и двух кейсов (мета после артефакта
→ PASS; продукт после артефакта → STALE) закрывает ось — рекомендация ниже.
