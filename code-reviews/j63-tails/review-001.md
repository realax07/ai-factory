## Проверено без замечаний

- `cmd_phase`: переименование локального `sc` → `scope_` корректно — внутри функции других обращений к модулю `sc`, сломанных затенением, нет; git вызывается только для записей, прошедших фильтр scope/flow, и кешируется на вызов.
- `cmd_finish`: перенос проверки реестра — для running/provisional поведение и код возврата (2) прежние; для blocked без `--pm-resume` при closed/released — тот же rc 2 с более точной причиной; accepted/returned по-прежнему идемпотентны раньше проверки.
- `mark_rejected_after_accept`: срабатывает на всех отказах после gate_end для обязательных стадий (zone_recheck, штамп J65.4b, commit_stage), provisional тоже помечается; повтор стадии: `gate_abandon` → `flowctl release` из needs_attention, новая попытка — свежий gate без `accepted`. `rejected_after_accept` не входит в `RECORD_CLOSED`/`PHASE_COMPLETED_STATUSES`/`RUNNER_REVIEW_STATUSES` — не засчитывается; повторный finish по такой записи — blocked.
- Маркер пакета: в git-dir worktree (`.git/worktrees/<name>`), в дерево/коммит не попадает; `ensure_worktree` всегда дает отдельный worktree; удаляется вместе с worktree. Для основного клона (только в тестах) — `<repo>/.git/package-runner.json`, gc его не трогает (gc сносит только worktree из реестра).
- `gc --apply` исполняет только строки `worktrees.remove` плана, guard применяется при построении плана.
- `cmd_close`: только `accepted` + `expect_from="finished"` под локом; повтор по closed — rc 0 `idempotent`.
