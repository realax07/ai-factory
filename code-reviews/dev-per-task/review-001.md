## Что проверено и в порядке

- `per_task_ids`: фильтр QA-раздела `flow_check.QA_SECTION` и меток
  ops/docs/design по всем скобочным меткам строки совпадает с
  `flow_check.closed_dev_tasks` (Н11); `title` из `_task_lines` не содержит
  чекбокс; сорт по Кану стабильный по порядку файла, цикл дает RunnerStop.
- Развертка в `cmd_run`: вставка `manifest["stages"][at+1:at+1]` во время
  `for` по списку корректна (следующие итерации идут по под-стадиям); `expanded`
  не входит в done, поэтому на resume родитель снова разворачивается из
  `state["expanded"]` и done-под-стадии пропускаются. `--task` уходит в
  `flowctl prepare` (gate_begin:1182-1183). Zones, inputs и gate под-стадия
  наследует через `dict(stage, …)`.
- parse_manifest: проверка bool, запрет для не-pi, `task_id` и `verdict`;
  на hermes/gate/stand не влияет (для не-pi `per_task: true` дает ManifestError,
  `false` игнорируется).
- J65.4b и provenance: штамп ставится только стадии с verdict (под-стадии без
  verdict не штампуются); `record_review_provenance` идет по
  `manifest["stages"]` в памяти, куда под-стадии уже вставлены (в том числе на
  resume), и собирает их `delegation_id` в authors. Корректно.
