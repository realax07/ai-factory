### 4. Worktree-сверка «артефакт ↔ дерево» — ЗАКРЫТО, обратно совместимо

`flowctl regress` пишет `- worktree: <repo>` в артефакт; ворота при наличии поля требуют HEAD дерева == commit прогона (через настоящий `git rev-parse`, не строку), fail-closed на нечитаемом дереве. Мои live-пробы на свежих репо:

| Проба | Исход |
|---|---|
| Артефакт от чужого дерева (commit и worktree чужие) | STALE ✓ |
| Артефакт **без** worktree-поля, commit чужой | STALE по прежнему commit-пункту — семантика не изменилась ✓ |
| Артефакт без поля, commit == HEAD | PASS — прежнее поведение, обратно совместимо ✓ |
| Commit == HEAD, но worktree уехал вперед после прогона | STALE ✓ |
| То же дерево, подтянутое назад к commit прогона (`reset --hard`) | PASS ✓ |
| worktree-путь не git-дерево / не существует | STALE, молчаливого пропуска нет ✓ |

Сценарий из фокуса «регресс-артефакт от чужого дерева → STALE» подтвержден; «артефакт без поля → прежняя семантика» — подтвержден (старые артефакты и тесты формата без поля проходят как раньше, TC это тоже фиксирует). E2E TC-R3-009: реальный `flowctl regress --final` пишет поле, ворота пропускают.
