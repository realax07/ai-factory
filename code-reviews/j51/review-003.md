## Проверка пунктов фокуса

### 1. Ворота не ломают существующие сценарии — ЗАКРЫТО

- Ворота живут в `check_change` (`check_regress_final` вызывается только там): `[chore]`/`[docs]`/`[ops]` идут через `check_chore`/`check_ops`/`check_bug` — их артефакты не тронуты; полный регресс 695 passed воспроизведен на этой ветке (включая все pr_validate-сьюты). BUG-PR без regress-final проходит (`check_bug` ворот не вызывает) — контракт «BUG-PR без regress-final обязан проходить» выполнен.
- REGRESS_FINAL_MISSING/STALE не маскируют прежние коды: все прочие missing-пункты накапливаются в общий список, воротный вызов — `extend`, не замена.

### 2. Подделка/обход — ЗАКРЫТО (пробы)

- **regress-\<N\>.md не финальный:** путь к артефакту жестко `regress-final.md`; нумерованные не читаются вовсе (TC-J51-022 подтвержден; `regress_next_number` в flowctl симметрично не считает final нумерованным).
- **hash-сверка реальна:** `_regress_commit_problem` гоняет настоящий `git merge-base --is-ancestor` + `rev-parse`, не строковое сравнение. Мои пробы: rebase-переписанный хеш на новой голове → `REGRESS_FINAL_STALE «не совпадает с HEAD и не является его предком»`; прародитель старше последнего касания измененного файла → STALE; прародитель свежее → PASS; сокращенный префикс HEAD — принимается (корректно); не-hex commit → «артефакт не от flowctl regress».
- **stale на новой голове → FAIL** — подтверждено пробой B и TC-J51-026.
- Verdict-парсинг требует точного `PASS` (FAIL/WARN/нечитаемый — не засчитаны), т.е. рекомендация review-002 («ворота должны разбирать verdict, а не только rc») выполнена. Дата парсится по поле `date` с fallback на mtime; поле `commit`/`verdict`/`date` совпадают с фактическим форматом артефакта flowctl (e2e-проба на реальном `flowctl regress --final` — ворота пропускают).

### 3. regress_runner-промпт — ЗАКРЫТО (с двумя минорами)

- Зона «только `test-model/regress/<change-id>/`» не пересекается ни с одной чужой зоной реестра (`qa_regression_analyst` пишет `test-model/regression/` — другой каталог). SELF_REVIEW-лазейки нет: роль не касается `code-reviews/`, не выносит approve, «зеленый без факта прогона запрещен» прописано; push НЕТ; FAIL не-флак → возврат dev'у. Узкий бриф соответствует уточнению Заказчика.
- **Минор #1:** роль добавлена в реестр `agents/README.md`, но НЕ в машинную политику `scripts/role_zone_policy.ROLE_ZONE_POLICY` — по докстрингу модуля роль вне таблицы получает пустую политику = резервация/запись запрещены. Делегация regress_runner через flowctl prepare с зоной `test-model/regress/<C>` получит отказ; артефакты `test-model/regress/` не покрыты ни одной ролью политики. Артефакт пишет сам flowctl (обход не нужен), поэтому функционально ворота работают, но политика и реестр разошлись. Заодно `POLICY_TABLE_DIGEST` запинен на `agents/README.md@85bba56` (2026-10-02) — таблица в этом PR отредактирована, audit-поле policy_version теперь ссылается не на ту редакцию.
- **Минор #2:** `check_regress_final` собирает путь из `change_id` без валидации — `check_regress_final(repo, "../../evil")` читает (только читает) regress-final.md вне репозитория и эхом выводит change-id в сообщение. Эксплуатация бессмысленна (чужой файл все равно должен содержать верный commit/дату), но каноничный regex из flowctl (fix review-001 #1) стоит переиспользовать и здесь — единая валидация change-id на обоих концах.

### 4. MAP J51 [x] vs критерии закрытия — НЕ ЗАКРЫТО (major)

Критерии файла бэклога: worktree в prepare ✓ (J51.1, #125), flowctl regress ✓ (J51.2, #125), ворота ✓ (этот PR), **«Прогнано на живом параллельном пакете (два агента, два worktree, ноль гонок)» — не выполнен и не отмечен**:

- `~/.hermes/state/flowctl_state.json`: 0 прогонов после 2026-10-15, 0 записей с worktree за всю историю реестра;
- PLAN.md (строка про «6 параллельных запусков, worktree-изоляция, 0 инцидентов») — это Релиз 2 от 2026-09-22, т.е. до открытия J51 (2026-10-16), к механизации J51 отношения не имеет; в проектных PLAN (ekotov-wiki) живого параллельного пакета после 2026-10-17 не найдено.

Чекбокс `[x]` с текстом «Реализовано волной 2» заявляет закрытие J51 целиком. Ровно это и есть отказ от механики в пользу семантики, против которого J51 и был заведен (решение Заказчика дословно в файле бэклога: «на семантике — ты опять забудешь»). **Фикс:** либо прогнать живой параллельный пакет (два агента, два worktree) и вписать фактуру в MAP/бэклог, либо оставить J51 открытым с пометкой «волна 2 (код) готова, живой прогон — отдельным шагом».
