# PLAN-gates-stats: дисциплина роста ворот (J65.9)

**Флоу: 4** — обслуживание фабрики: инструмент ПМ над памятью движка.

## Решение Заказчика

«Да, погнали» (2026-11-11) на порядок J65.10 → J64.10 → J65.9.

## Состав

- `scripts/gates_stats.py` + подкоманда `flowctl gates-stats [--state]
  [--since] [--until] [--json]`: гейты gate_runner × статус, решения
  prepare и коды отказа `REASON_CODES` (всего и по этапам), итоги циклов,
  дефекты finish, события энфорсера; «без срабатываний за период» — гейты
  без FAIL/ERROR и коды без отказов. Источники — существующие файлы state
  (новых журналов нет).
- Правило в `docs/README-flow-control.md`, раздел «Дисциплина роста ворот»:
  новый гейт — при повторе класса инцидента или высокой цене промаха;
  квартальный пересмотр по `gates-stats`, решение — Заказчик, резолюция — в
  бэклоге J65.
- Тесты `tests/unit/test_j65_gates_stats.py` (TC-J65-GST-001…005), в т.ч. на
  записи настоящего flowctl.

## Не видно (честно)

Отказы prepare до записи цикла (ZONE_OUTSIDE_POLICY, защищенные пути J3) —
flowctl их только печатает; STOP раннера — в state рядом с планом проекта.
Кандидат: журнал ранних отказов prepare.

## За Заказчиком

Первый пересмотр (приемка ТЗ J65.9) — на машине фабрики (VPS), где лежит
боевой state: `python3 scripts/flowctl.py gates-stats --since <начало
квартала>`; резолюцию — строкой в бэклог J65. На машине разработки state —
только следы тестов, пересмотр по нему не показателен.
