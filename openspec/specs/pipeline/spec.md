# Pipeline Specification

## Purpose
Общие правила конвейера агентов AI Factory: порядок ролей, передача работы, эскалации. Все специализированные спеки (requirements, system-analysis, qa-*) уточняют эту спеку для своего этапа.

## Requirements

### Requirement: Передача работы через артефакты
Агенты MUST передавать результаты работы только через файлы в репозитории проекта. Агент MUST NOT считать работу завершенной на основании контекста диалога.

#### Scenario: Попытка передачи результатом сообщения
- **GIVEN** агент завершил обработку в диалоге
- **WHEN** выходной артефакт не записан в репозиторий
- **THEN** работа агента не считается завершенной
- **AND** следующий агент конвейера вправе не принимать задачу

### Requirement: Валидация входа по контракту
Агент MUST проверить входной артефакт по условиям входа соответствующего контракта до начала работы. При несоответствии агент MUST остановиться и вернуть артефакт через проектного менеджера.

#### Scenario: Дефектный входной артефакт
- **GIVEN** входной артефакт не проходит условия входа контракта
- **WHEN** агент обнаруживает это при проверке входа
- **THEN** агент не выполняет основную работу
- **AND** агент возвращает список дефектов проектному менеджеру

#### Scenario: Валидный входной артефакт
- **GIVEN** входной артефакт проходит все условия входа
- **WHEN** агент завершил проверку входа
- **THEN** агент приступает к основной работе

### Requirement: Порядок этапов конвейера
Работа MUST проходить этапы в порядке: сбор требований → системный анализ → разработка → QA-контур. Этап MUST NOT начинаться до завершения предыдущего.

#### Scenario: Попытка старта этапа без входного артефакта
- **GIVEN** входной артефакт этапа отсутствует в репозитории
- **WHEN** поступает запрос на запуск этапа
- **THEN** этап не запускается
- **AND** проектный менеджер получает уведомление об отсутствии входа

### Requirement: Единоличное разрешение конфликтов запрещено
Агент MUST NOT разрешать противоречия в требованиях, спеках или артефактах по собственному усмотрению. Противоречия MUST эскалироваться проектному менеджеру.

#### Scenario: Противоречие во входном артефакте
- **GIVEN** два пункта входного артефакта противоречат друг другу
- **WHEN** агент обнаруживает противоречие
- **THEN** агент фиксирует противоречие и останавливается
- **AND** решение принимает Заказчик через проектного менеджера

### Requirement: Статусы инструкций агентов
Каждая инструкция агента MUST иметь статус: активен, резерв или черновик. Работу по задаче MAY выполнять только агенты со статусом «активен».

#### Scenario: Задача назначена агенту в статусе резерв
- **GIVEN** инструкция агента имеет статус «резерв»
- **WHEN** проектный менеджер назначает задачу этому агенту
- **THEN** назначение требует явной активации статуса в реестре agents/README.md
