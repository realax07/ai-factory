# Artifacts Specification

## Purpose
Форматы и расположение артефактов конвейера: условия входа и выхода каждого этапа. Тексты условий — источник правды; agents/*.md и contracts/*.md MUST соответствовать этой спеке.

## Requirements

### Requirement: Требования как вход системного анализа
Системный аналитик MUST принимать работу только при наличии `requirements.md`, содержащего разделы: общее описание, аудитория, функциональные требования (FR-N), нефункциональные требования (NFR-N), приоритеты MoSCoW, ограничения, открытые вопросы.

#### Scenario: requirements.md полный
- **GIVEN** файл requirements.md содержит все 7 разделов
- **WHEN** системный аналитик проверяет вход
- **THEN** работа по системному анализу разрешена

#### Scenario: requirements.md без приоритетов
- **GIVEN** раздел «Приоритеты» отсутствует или пуст
- **WHEN** системный аналитик проверяет вход
- **THEN** артефакт возвращается БА-агенту со списком дефектов

### Requirement: OpenSpec-пакет как выход системного анализа
Системный аналитик MUST публиковать результат в структуре `openspec/changes/<change-id>/` (proposal.md, specs/, design.md, tasks.md) и `sdd.md`. Каждый Requirement MUST иметь хотя бы один Scenario в формате GIVEN/WHEN/THEN.

#### Scenario: Пакет без tasks.md
- **GIVEN** change-пакет не содержит tasks.md
- **WHEN** потребитель проверяет условия контракта 2
- **THEN** пакет не принимается в работу

#### Scenario: Requirement без сценария
- **GIVEN** Requirement в спеке не имеет ни одного Scenario
- **WHEN** QA-аналитик проверяет вход
- **THEN** пакет возвращается системному аналитику

### Requirement: Трассировка требований
Каждый Requirement в спеке MUST ссылаться на идентификатор ТЗ (FR-N/NFR-N). Каждый пункт чеклиста и каждый тест-кейс MUST иметь ссылку на источник. Матрица трассировки MUST находиться в sdd.md.

#### Scenario: Requirement без источника
- **GIVEN** Requirement не ссылается на FR-N/NFR-N
- **WHEN** любой потребитель проверяет артефакт
- **THEN** элемент помечается дефектом трассировки

### Requirement: Директории QA-артефактов
QA-артефакты MUST располагаться: чеклисты — `test-model/checklists/`, новые тест-кейсы — `test-model/new/<change-id>/`, ревью — `test-model/reviews/<change-id>/`, одобренные кейсы — `test-model/approved/<change-id>/`, баг-репорты — `test-model/bugs/`.

#### Scenario: Кейсы размещены в новой папке
- **GIVEN** автор тест-кейсов завершил работу
- **WHEN** файлы кейсов записаны в test-model/new/<change-id>/
- **THEN** ревьюер вправе начать ревью

#### Scenario: Автотесты начаты до одобрения
- **GIVEN** кейсы отсутствуют в test-model/approved/<change-id>/
- **WHEN** автоматизатор получает задачу
- **THEN** работа не начинается до появления одобренных кейсов
