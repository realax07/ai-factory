## ADDED Requirements

### Requirement: Сменный исполнитель агентных стадий
Агентная стадия пакетного раннера MUST задаваться как `run: <исполнитель>:<роль>` и вызывать исполнителя только через общий интерфейс исполнителей. Ворота стадии (prepare, резервация зоны, сверка git diff с зоной, гейты, provenance) MUST выполняться раннером одинаково для любого исполнителя. Добавление исполнителя MUST сводиться к одному модулю исполнителя без правок flowctl, gate_runner и session_check. Неизвестный исполнитель в манифесте MUST давать ошибку манифеста до запуска стадий.

#### Scenario: Стадия на другом исполнителе проходит те же ворота
- **GIVEN** манифест пакета задает стадию `run: stub:dev` вместо `run: pi:dev`
- **WHEN** раннер исполняет пакет
- **THEN** стадия проходит prepare, резервацию, сверку диффа, гейты и provenance так же, как стадия pi

#### Scenario: Неизвестный исполнитель
- **GIVEN** манифест задает `run: nosuch:dev`
- **WHEN** раннер читает манифест
- **THEN** раннер останавливается с ошибкой манифеста, ни одна стадия не запускается

### Requirement: Модель и провайдер роли из реестра
Модель и провайдер агентной стадии MUST браться из реестра ролей agents/roles.json; манифест MAY переопределить их ключами `provider` и `model` стадии. Значения по умолчанию в коде раннера MUST NOT использоваться для роли, описанной в реестре.

#### Scenario: Переопределение модели в манифесте
- **GIVEN** реестр задает роли dev модель A, стадия манифеста — `model: B`
- **WHEN** раннер вызывает исполнителя
- **THEN** исполнитель получает модель B и провайдера роли из реестра

### Requirement: Обход исполнителя виден вотчдогу
Вотчдог обхода MUST сверять активные запуски каждого исполнителя с живыми резервациями реестра сессий: запуск исполнителя в рабочем каталоге без живой резервации MUST фиксироваться инцидентом BYPASS. Для делегаций Hermes MUST сохраняться сверка с записями flowctl.

#### Scenario: Ручной запуск исполнителя мимо раннера
- **GIVEN** в worktree запущен процесс исполнителя pi, резервации на этот worktree нет
- **WHEN** отрабатывает вотчдог
- **THEN** фиксируется инцидент BYPASS с исполнителем и рабочим каталогом

#### Scenario: Запуск раннером
- **GIVEN** раннер запустил исполнителя в worktree пакета после prepare и run
- **WHEN** отрабатывает вотчдог
- **THEN** инцидента нет
