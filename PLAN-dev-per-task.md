## Возврат ревью review-001 (2 major)

Цепочка зависимых задач на настоящих воротах получала DENY: dev_task
требует approve-ревью зависимостей (J10), а ревью шло одной стадией после
всех dev. Исправлено: `review: <роль-пак>` разворачивает пары dev-N →
review-N (code_review по задаче, вердикт `code-reviews/<pkg>/review-N-001.md`
— файл, который засчитывает J10); зависимые задачи без `review:` — STOP на
развертке. Зависимость на открытую не-dev/несуществующую задачу — STOP
сразу; per_task только для pi:dev без optional; коллизия id — STOP; нет
движка на resume — STOP, не AttributeError.

## Возврат ревью review-002 и решение Заказчика (2026-11-11)

Тупик на ревью-стадии: code_review Флоу 1 не принимает задачу с закрытым
чекбоксом, а dev_task следующей требует закрытую одобренную зависимость; dev
закрывает чекбокс по своему промпту. Развилка — Заказчику; решение: «Чекбокс
ставит раннер». При per_task с review бриф dev запрещает закрывать чекбокс
(закрыл — STOP стадии), после approve пары раннер ставит `[x]` своим
коммитом. Правила ворот не меняются. Тест на настоящих проверках ворот
(flow_state.inspect + check_code_review + _deps_findings) по шагам dev-1.3 →
review-1.3 → dev-1.2 (TC-J64-DPT-006). Повторная итерация ревью — дописать в
тот же файл (append-only, решает последний заголовок); пустая зона ревьюера
— STOP на развертке.
