# ТЗ 04. Сессии, зоны записи и привязка к Worktree

**Flow:** 4. **Зависимость:** 02–03. **Результат:** `session_check.py`/библиотека admission и проверка результата сессии.

## Предзапусковой контроль

Запрос содержит project, repo, owner_pm, delegation_id, role, Flow, scope, список разрешённых путей записи, branch, worktree, base SHA, snapshot digest. Зоны выводятся из реестра ролей и контракта; агент не может расширить свою зону текстом goal. Использовать канонические пути и glob-семантику с тестами на вложенные пути, symlink и конфликт префиксов.

Перед запуском: проверить status роли `active`, валидность проекта и реестра, отсутствие пересечения зон активных сессий в том же repo, уникальность delegation_id, соответствие branch/worktree и отсутствие чужого `SESSION.md`. Резервировать зону атомарно под локом с записью через временный файл + rename. Повторный запрос с тем же id и идентичным payload идемпотентен; иной payload отвергается. `check` без reservation не гарантирует права на последующий spawn.

## Worktree boundary

Создавать worktree через существующий `session_worktree.sh`, затем проверять `git rev-parse --show-toplevel`, branch и `SESSION.md`. Runner запускает агентскую команду с `cwd` именно в этом worktree и передаёт абсолютный путь. После завершения сверить `git status`, changed paths (`base SHA..HEAD` плюс незакоммиченные), разрешённую зону, branch и отсутствие изменений в соседних деревьях. Текстовое указание cwd само по себе не является физической изоляцией; локальный запуск без песочницы не обещает, что процесс технически не может писать вне worktree. Обнаруженный выход за зону → блок приёмки и инцидент.

## Жизненный цикл

`reserved → running → finished → accepted/returned/failed → closed`. У каждой смены есть evidence и причина. После падения процесса reservation не удалять автоматически: `reconcile` сверяет PID/процесс, worktree, git status и лог, помечает `stale/needs_attention`. Повторный запуск требует явного решения ПМ. Снимать worktree лишь при чистом дереве и доказанном сохранении/приёмке нужных коммитов; не использовать принудительное удаление при незакоммиченных файлах. Для возврата и failed сохранять артефакты на разбор.

## Ограничения совместимости

Текущий `pm_bounds_check.py --sessions` проверяет обязательные поля и отдельное правило пар; он не является проверкой пересечения зон и неправильного worktree. Новый контроль дополняет его. Схему `active_sessions.json` менять миграцией с резервной копией и чтением старого формата; path к реестру передавать явно для тестов.

## Приёмка

- Два конкурентных `reserve` для пересекающейся зоны: ровно один успех.
- Разные непересекающиеся зоны в отдельных worktree допускаются.
- Чужой cwd, branch, symlink за пределы зоны и изменение в соседнем worktree дают отказ.
- Падение runner сохраняет запись и файлы, `reconcile` ничего не удаляет молча.
