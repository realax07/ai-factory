# Детерминированный Flow Control для AI Factory

## Цель

Встроить в существующую AI Factory исполняемую модель состояния и переходов. По репозиторию, Git и реестру сессий система должна объяснять: что уже доказано, какие действия разрешены, какой агент может их выполнить и почему действие заблокировано. Запуск агента остаётся отдельным слоем над этими решениями.

Это набор задач для backlog, а не утверждение, что описанные ниже компоненты уже реализованы. Исходная версия для сверки: архив `ai-factory-main.zip` от 27.09.2026. Перед реализацией сверить требования с актуальной веткой: архив может отставать.

## Основной принцип

- Агент принимает интеллектуальные решения в границах роли.
- `Flow State` извлекает факты и отмечает неизвестное.
- `Transition Validator` разрешает либо запрещает конкретное действие.
- `Orchestrator` исполняет только разрешённое действие.
- `flow_check.py`, `pm_bounds_check.py`, `pr_validate.py`, OpenSpec и тесты остаются независимыми deterministic gates.
- Git, файлы, результаты CI и реестр сессий дают evidence. Самоотчёт агента не считается доказательством.

## Общие ограничения

1. Не вводить LangGraph, CrewAI, Temporal, БД событий или YAML-язык состояний для первого MVP. Использовать Python stdlib и существующие команды.
2. Не заменять `flow_check.py` и `pm_bounds_check.py` заглушками; не менять их exit codes и режимы без отдельного теста совместимости.
3. Состояние вычислять по области `project + change/bug/chore + task`, а не одним линейным статусом всего репозитория. Параллельные задачи и QA-ветки допустимы по контрактам.
4. Невозможность прочитать источник, неоднозначность, отсутствующее evidence и ошибка gate дают `DENY/UNKNOWN`, а не разрешение по умолчанию.
5. Не хранить токены, секреты и полные промпты в execution log; хранить ссылки и digest.
6. Не делать автоматический push, merge, release, deploy или старт новой крупной фазы. Действующие ворота решения заказчика из `AGENTS.md` обязательны.
7. Изменение процесса вести в порядке: `openspec/specs/` → `contracts/` → инструкции ролей и скрипты. Сначала зафиксировать решение заказчика и выбранный Flow в плане задачи.

## Общая приёмка

На тестовом репозитории CLI показывает состояние и допустимые следующие действия; отвергает обход порядка, чужую роль, пересекающиеся зоны, неправильный worktree и устаревший review; после прерывания безопасно восстанавливается из фактов. Существующий пилот и CI продолжают проходить старые проверки. Команды и ожидаемые exit codes описаны в README фабрики.
