## 3. Дисциплина ПМ (директивы Заказчика)

- **ТЗ для dev — только из артефактов** (спека, sdd). Галлюцинация ТЗ = эскалация СА (урок R1.3).
- **Классификация флоу объявляется Заказчику до запуска** (1–5; см. AGENTS.md п.13).
- **Артефактные проверки уводить в CI** (J6) — ПМ не живой валидатор. Принцип: где можно скриптом — скриптом.
- **Git-инциденты зеркалить честно в чат** (что случилось, что потеряно, как восстанавливаем).
- **Верификация: «не поверить отчету, а проверить фактами»** — ветки/диффы/прогоны руками при приемке. Самоотчет сабагента не доказательство.
- **1 задача = 1 dev-сабагент + отдельный ревьюер**; ПМ не совмещает автора и ревьюера.
- **Параллельные сессии — git worktree на сессию** (E5); зоны записи — из таблицы agents/README; пересечение — последовательно (теперь проверяет session_check).
- **Не диспатчить delegate_task в ходе чужого входящего сообщения** (см. §1, баг #92859).

## 5. Детерминированный слой (J28, change add-deterministic-flow)

С 2026-10-02 конвейер имеет исполняемую state-машину (ветка deterministic-flow,
после слияния — в составе фабрики). Компоненты и назначение:

| Скрипт | Назначение | Режим |
|---|---|---|
| `flow_state.py` | read-only снимок фактов по scope (repo+project+flow+change+task) | чистый |
| `flow_transition.py` | check_action → ALLOW/DENY/UNKNOWN + коды причин; графы Флоу 1–5; этапные ворота → HUMAN_APPROVAL_REQUIRED | чистый |
| `session_check.py` | атомарная резервация зон, post-check границы (renames/symlink), reconcile | меняет реестр |
| `gate_runner.py` | единый запуск ворот (digest/timeout/STALE), provenance review (sidecar), audit JSONL | меняет логи |
| `flowctl.py` | оркестратор: prepare/run/finish/status/reconcile, adapter=manual, идемпотентность | меняет state |
| `flow_mode.py` | переключатель shadow/enforcing (enforcing: DENY/UNKNOWN блокируют) | меняет режим |
| `flow_ids.py` | грамматика scope флоу 1–5 (J65.3): движок, flowctl и энфорсер — по одному источнику | чистый |
| `role_zone_policy.py` | политика зон ролей для ворот из реестра `agents/roles.json` (J65.1); таблицы ролей — `gen_role_docs.py` | чистый |
| `package_runner.py` | пакетный раннер по манифесту `pipeline:` плана: агентные стадии `<исполнитель>:<роль>` через `flowctl prepare/run/finish`, сверка диффа с зоной, коммит стадии (J62/J63/J65.5) | меняет worktree/state |
| `executors/` | исполнители агентных стадий (pi, stub, hermes); новый исполнитель — один модуль (J65.5) | — |
| `gates_stats.py` | `flowctl gates-stats`: срабатывания гейтов и кодов отказа для квартального пересмотра (J65.9) | чистый |
| `ci_local.py` | прогон сьюта и flow_check в условиях CI (клон глубины 1, пустой HOME, J65.12) | чистый для репо |

- **Режимы:** shadow (решения вычисляются, не блокируют) → enforcing (блокируют). Переключение — решение Заказчика: `python scripts/flow_mode.py set enforcing --by customer`.
- **Пройденные shadow-уроки (не повторять):** QA-порядок проверяется по пакету, не по глобальным каталогам (S5); release строго после archive (3.2-Б); архивация — sa (3.3-А); provenance обязателен с diff_digest (M3); SKIPPED обязательного gate = не-PASS (B1).
- **Ревью-дисциплина подтверждена:** 4 RETURN из 6 ревью с real-находками (8 major) — ревьюер с live-пробами ловит то, что тесты автора пропускают. Не пропускать ревью «потому что и так работает».
