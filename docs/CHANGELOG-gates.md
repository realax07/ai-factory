# CHANGELOG ворот

Журнал версий ядра ворот: какие коды отказа появились, изменились или сняты.
Версия ядра — git-тег `core-vX.Y` на коммите main (J65.6). Коды — стабильные
машиночитаемые причины отказа (контракт `contracts/flow_control_contract.md`
§9). Новый код без строки здесь — красный тест
`tests/unit/test_j65_gates_changelog.py`.

Правила ведения:

- новый код отказа или смена смысла — строка в разделе следующей версии;
- снятый код не удаляется из истории: строка «снят» в разделе версии, где
  его не стало;
- рост ворот — по правилу «Дисциплина роста ворот» `docs/README-flow-control.md`
  (у нового гейта — причина-инцидент и срок пересмотра).

## core-v1.0 — 2026-11-17 (J65.6, «ядро готово»)

Первая версия ядра. Критерий (резолюция J65.6 в
`backlog/J65-ТЗ-единый-источник-правды-2026-11-03.md`):

1. Ворота и проверки в `scripts/` не знают устройства данных Hermes: реестр
   делегаций, транскрипты и логи читает только исполнитель
   `scripts/executors/hermes.py`. Исключения: установщики (`factory_init`,
   `factory_bootstrap`), модуль путей `factory_paths` и утилита платформы
   Hermes `session_watchdog` (лечит роутинг Telegram-гейтвея и сигналит о
   залипших и недоставленных делегациях Hermes — проверка самой платформы,
   решение Заказчика «Исключение: утилита Hermes»). Границу держит
   `tests/unit/test_j65_core_ready.py`.
2. Эталонный межагентный прогон Флоу 1 (`tests/fixtures/reference-run/`)
   проходит на двух исполнителях: `pi` (заглушка бинаря) и `stub`, в CI на
   каждом PR.

### Изменения в этой версии

- `pr_validate`: независимость ревью проверяется и без Hermes — по state
  раннера, реестру делегаций через адаптер или provenance-sidecar
  `gate_runner record-review`. Реестров нет: в CI — пометка `SKIPPED` в
  выводе и в итоговой строке (PR не валится, проверит pre_merge ПМ (`gate_runner --pr-id`; без PR-контекста шаг pr_validate — SKIPPED)),
  вне CI — отказ. Раньше
  недоступный `state.db` молча засчитывал любое ревью (fail-open).
- `pr_validate`, Флоу 2: PR `[BUG-…]` требует `code-reviews/<bug-id>/` с
  последним вердиктом approve и доказательством независимости ревьюера.
- `pr_validate`: provenance-sidecar `gate_runner record-review` принимается
  вместо строки `Reviewer-Delegation` при согласованных полях (scope,
  вердикт, автор ≠ ревьюер, коммит, digest). Ревьюер `deleg_…` проверяется
  по реестрам; у ревьюера внешнего агента (`<агент>:<id>`, п.21 AGENTS.md)
  реестра нет — в CI SKIPPED, вне CI отказ.

### Статусы ворот

| Код | Смысл |
|---|---|
| `ALLOW` | решение движка: действие разрешено |
| `DENY` | отказ с кодами причин (все, не первая) |
| `UNKNOWN` | проверка невозможна (нечитаемый источник, нет provenance) — не разрешение |
| `PASS` | гейт пройден |
| `FAIL` | гейт не пройден |
| `SKIPPED` | гейт или проверка неприменимы по явному правилу; в pr_validate — независимость ревью не проверяема в CI (J65.6) |
| `SKIP` | flow_scope_check/flow_preflight: проверка не выполнена — неприменима к PR или нет входа (merge-base не определен, HEAD не читается) |
| `ERROR` | гейт не выполнился (ошибка запуска) |
| `WARN` | предупреждение без блокировки |
| `WARNING` | предупреждение энфорсера/статистики ворот без блокировки |
| `STALE` | доказательство устарело: HEAD изменился после gate-отчета (flowctl finish) или вердикт выдан на другой коммит (раннер) |
| `STOP` | раннер остановил стадию, ждет ПМ |
| `BYPASS` | вотчдог: запуск исполнителя или делегация мимо ворот (`proc:<исполнитель>:<pid>`) |
