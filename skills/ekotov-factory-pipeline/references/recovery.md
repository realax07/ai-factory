# Восстановление конвейера (рецепты)

Вынесено из SKILL.md (лимит размера). Глубина, нужная только при восстановлении/расследовании.

## Восстановление ветки пакета после чужой базы

Если коммиты делегации легли на ветку, чья история не содержит базовых коммитов пакета (переключения между ветками при параллельной работе), восстановление: найди «потерянную» цепочку в `git reflog` (коммиты SA/мокапы видны по сообщениям), `git branch -f <branch> <последний SA-коммит>`, затем `git rebase --onto <SA-коммит> <старый-родитель-мокапов> <branch>` — мокапы поверх SA-истории; проверь `ls` артефактов пакета на ветке + `python3 scripts/flow_check.py .` + пуш `--force-with-lease`. `git fsck --lost-found` находит dangling-коммиты, которых нет ни в одной ветке. Релизный журнал и decisions-файлы держи в той ветке, на которой стартовал пакет.

Внешние багрепорты (приемка, политика-vs-дефект, Флоу 2): `references/external-bugreports.md`.

## Восстановление статуса конвейера (начало сессии)

Статус собирается из живых источников, не из памяти — всегда в одном порядке:

1. `git log --oneline -5 origin/main` + текущая ветка/`status -sb` — что фактически влито и где висит некоммитнутое.
2. Незакрытые задачи: `grep '^- \[ \]' openspec/changes/<id>/tasks.md` — позиция в пакете.
3. Реестры: не-completed записи `active_sessions.json` + статусы `runs` в `flowctl_state.json` — зомби/running-хвосты.
4. Ручной прогон watchdog — накопленный ack-долг виден сразу (см. секцию Вотчдог).
5. Свежие review-файлы и reports (`code-reviews/`, `test-model/reviews/`, `/tmp/report-*.md`) — вердикты и хвосты последней делегации.

APPROVE-коммит, лежащий на фиче-ветке после влития основного PR — не «работа в процессе», а хвост к закрытию: пуш + PR (маркер [chore] в title ПРИ создании) + merge по зеленых чеках, потом [x] в tasks.md. Доклад Заказчику: этапы ворот (prepare/reserve/check/gates/provenance: PASS/DENY/UNKNOWN/SKIPPED), что сделано, что в работе, какая развилка впереди.
