# Ворота regress-final: грабли первого боевого применения (J51.2/J51.3)

## Маппинг и свежесть

- Маппинг доменов дедуплицируй ДО прогона: частичные домены (tests/api, tests/web) при наличии общего tests/ сворачивай в один прогон — дубль рождает коллизию conftest для голых импортов еще на коллекции (exit 2 до тестов).
- Свежестная сверка артефакта исключает мета-пути (code-reviews/**, test-model/regress/**, test-model/reviews/**): артефакт всегда новее удостоверяемого кода, а мета-коммиты не влияют на тесты — иначе ворота самоубийственны и каждое зеркало требует нового полного перегона.
- В CI не полагайся на локальные пути worktree из артефакта (не читаются — WARNING, инвариант несет commit-сверка) и на shallow-клон (checkout с fetch-depth: 0; иначе ancestry через GitHub API compare).
- Зеркалируя скрипты диффом — тащи импорт-замкнутость целиком (flowctl без session_check/pr_validate = AttributeError на первом прогоне); после зеркала — flow_check на проекте.
- Freeze tooling: никаких фабричных/зеркальных коммитов после последнего regress перед merge — каждый сдвиг «измененных файлов» = обязательный перегон.

## Мета ревью и покрытие задач (J10)

- Строка `Reviewer-Delegation: deleg_<id>` — deleg_ вплотную к метке (regex отсчитывает ≤6 не-алнум символов; текст между меткой и id ломает распознавание).
- Вердикт — заголовком `## Вердикт: approve`; в строке не упоминать return/доработку даже в контексте «был return, потом approve» — негативный regex бьет по подстроке.
- Файлы ревью, не подпадающие под грамматикy имен (review-<task>-<NNN>.md / review-<NNN>-<task>.md), покрывай review-mapping.json (файл → список task-id).
- Тестовые гонки: голый `from conftest import` ломает полную коллекцию (sys.modules['conftest'] затирается tests/web/conftest) — хелперы из корневого conftest через фикстуры; async-рендер + локатор = detached-узел — один атомарный evaluate, web-first expect ДО evaluate.

## Эшелоны (J54, решение Заказчика)

- Полный regress — пакетно на релиз; change = smoke + доменный regress своего куска; параллель — xdist с serial-fallback и изолирующими фикстурами (pytest-xdist в тест-окружения проектов).
- Freeze tooling и mirrors — до последнего regress (см. выше).

## Дисциплина общего чекаута

- Правь файлы только ПОСЛЕ `git checkout <целевая ветка>`: коммит мимо ветки стирается чужим `reset --hard origin/main`.
- После каждого таймаута/фонового обрыва находи свой коммит через `git reflog <ветка>`, не повторяй команду вслепую; пуш проверяй фактом `git log origin/<ветка>`, не отсутствием ошибки.
- Один и тот же урок на двух навыках — не дублируй: здесь механика ворот, в ekotov-wiki-ops — деплой-грабли нового сервиса.
