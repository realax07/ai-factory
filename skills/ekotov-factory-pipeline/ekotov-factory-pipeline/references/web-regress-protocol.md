# Web-регресс ekotov-wiki: релизный протокол (числа REPORT) и диагностика красноты

Дополнение к разделу SKILL.md «Тесты ekotov-wiki: api-сьют требует живой стенд».

## Релизные числа гоняются ТОЛЬКО против полного стенда с четырьмя env ВМЕСТЕ

```
env -u DB_PATH \
  EKOTOV_WIKI_BASE_URL=http://127.0.0.1:18443 \
  EKOTOV_WIKI_DB_PATH=/tmp/qa21-verify/app.db \
  EKOTOV_WIKI_IMAGES_DIR=/tmp/qa21-verify/images \
  EKOTOV_WIKI_AVATARS_DIR=/tmp/qa21-verify/avatars \
  /home/openclaw/venvs/wiki/bin/python -m pytest tests/web/ -q --tb=line
```

Механика отказов при неполном env (каждый коварен тем, что имитирует продуктовый дефект):

- **Без BASE_URL** — conftest поднимает автостенд только с app: search/images не подняты,
  ~37 паютов search-клиентов (combobox, tag-hints, search-builder). Диагноз: все фейлы в
  сьютах, ходящих через /api/search* — значит стенда нет.
- **Без DB_PATH** — cleanup-хук хвостов молча деградирует (`if not DB_PATH: return`):
  загрузки предыдущего теста остаются в сетке, порядок created_at DESC искажен — лайтбокс
  листает «не туда» (фейл «пришел не тот элемент»), счетчики едут.
- **Без AVATARS_DIR** — 15 teardown-ERROR (r5_crop, settings_profile, tooltip) + каскадный
  фейл avatar-preview visible у следующего теста (непочищенный аватар).
- **Без IMAGES_DIR** — файлы галереи не удаляются hygiene-хуками, каталог засоряется.

Автономный автостенд (`env -u ...` всего) — годится для смоука «соберется ли сьют»,
НЕ для сравнения с REPORT: числа будут другими.

## БД стенда — начисто перед релизным прогоном

Остаточные данные (категории прошлых прогонов, задачи QAT-%, чужие аватары) красят
не-галерейные сьюты тем же числом, что и продуктовые дефекты — число в REPORT недостоверно.
Пересоздание без рестарта search/images (app держит открытый sqlite — гасить):

1. Погасить app (порт 8080), rm app.db.
2. backend: `python -m app.db` → `python -m app.migrate_gallery` → `python -m app.migrate_r4`.
3. Seed: owner/wife (bcrypt) + категории «Дом/Работа/Личное». Секреты обязательны в env:
   DB_PATH + SECRET_KEY + AVATARS_DIR (config.py `_require` валит без них).
4. Поднять app обратно, health-check.

Готовые скрипты стенда: /tmp/qa21-verify/stand_up.sh (полный подъем app+search+images+nginx;
cwd сабсервисов — КОРЕНЬ сервиса services/search, не services/search/app — иначе
ModuleNotFoundError: app) и db_reset.sh (шаблон пересоздания БД). /tmp переживает не все
перезагрузки — при исчезновении восстановить из этого описания.

## Интерпретация красноты: симптом → причина

| Симптом | Причина | Действие |
|---|---|---|
| ~37f, все в search-клиентах | нет BASE_URL → автостенд без search | полный env + стенд с search/images |
| 1f лайтбокс «листает не туда», счетчики едут | нет DB_PATH → хвосты не чищены | полный env, пересоздать БД |
| 15 ERROR teardown + avatar-preview | нет AVATARS_DIR | добавить env |
| десятки f на НЕ-новых сьютах, категории ≠ seed | остаточная БД прошлых прогонов | пересоздать БД, перегнать |
| статика text/plain, ES-модули отброшены | nginx-стенд без mime.types | include /etc/nginx/mime.types |
| login 200, но UI старый при живом коде | кэш браузера, ?v= не бампнут | бамп static_v, чистый контекст |
| UI-ассерты зеленые, API-проверка KeyError на поле | page.request не шлет Secure-cookie на http → 401 | requests-сессия с secure=False (см. SKILL.md) |
| фикс-дифф делегации не на месте после пуша/мерджа | второй участник ветки закоммитил/ребейзнул поверх | git reflog + git fsck --unreachable; хостовые git-операции и делегация в одном дереве — сериализуй |

## Извлечение артефакта из лога делегации (когда правка «исчезла» из worktree)

Если сабагент отчитался «файл правлен», а в worktree его нет: правка могла быть
затерта Pull/checkout основного дерева или другим процессом. Лог делегации
(`~/.hermes/cache/delegation/live/<id>/task-N.log`) содержит результат каждой
patch/write_file с ПОЛНЫМ диффом — извлеки его оттуда (JSON-строки в result-записях,
`json.loads` с strict=False) и перепримени патчем. Прогоняй извлеченный код —
байт-в-байт копия из лога, включая хвостовые пробелы.

## Стенды сабагента переживают смерть родителя — проверяй порты перед подъемом

Сводка batch-complete числит фоновые процессы сабагента «TERMINATED», но uvicorn/nginx
реально переживают смерть родителя и держат порты (app 8080, search 8378, images 8379,
nginx 18443). Перед подъемом стенда: `ss -tln | grep -E '8080|8378|8379|18443'` — живой
nginx переиспользуй, мертвые сервисы поднимай заново с env
(DB_PATH/SECRET_KEY/EKOTOV_WIKI_DB_PATH/EKOTOV_WIKI_IMAGES_DIR, cwd = корень
сервиса, не его app/). Здоровье: curl /api/health каждого порта = {"status":"ok"}.

## Прогон руками в основной сессии — НЕ делай этого (ПМ-границы)

- **Не гоняй полный web-сьют foreground-вызовом**: у foreground-терминала кап ~600с,
  сьют идет ~12–15 мин — прогон молча уезжает в background-промоушен или режется на
  середине. Больше ~6 мин — сразу `terminal(background=true, notify=true)` +
  `process_manage wait`, лог в /tmp.
- **Два сьюта на одну БД стенда одновременно = карусель ложных фейлов**: параллельные
  (или наложенные во времени) прогоны сажают друг другу seed/cleanup — числа плавают
  при неизменном коде. Строго по одному прогону; «не сходится» — сначала чистая БД и
  одиночный прогон, потом диагноз.
- **Хвосты QAT-данных дают характерные фейлы**: 409 «category already exists» на seed,
  «ожидали N option — получили N+чужие» в селектах категорий, двойные чипы от чужих
  задач. Прежде чем квалифицировать фейл продуктовым — снеси QAT-% (задачи, категории,
  теги; FK-порядок: task_tags/image_tags первыми) скриптом db_reset и перегони
  одиночный файл. Ручные sqlite-DELETE без `.schema` впереди — schema-ползание.
- **Стенд из main — через git worktree от origin/main**
  (`git worktree add /tmp/<slug> origin/main`), не checkout основного дерева: дерево
  бывает занято веткой делегации. nginx-конфиг — копия прошлого с подменой alias-
  путей на worktree; сервисы поднимать из worktree (cwd = корень сервиса).
- **Стенд нельзя делить между ПМ-прогоном и сабагентом-фиксером одновременно**: они
  чистят БД друг у друга и гасят сервисы. Сабагенту — отдельные порты либо явная
  очередь («стенд поднят, не пересоздавай, чисти QAT-хвосты перед прогоном»).

## Независимая верификация отчета QA (ПМ-минимум)

Перегнать полный web-регресс на чистом стенде с полным env и сверить числа REPORT.
Любое расхождение — сначала env-протокол и чистота БД, потом код: расхождение почти всегда
воспроизводимости окружения, не продукта. Лимит ручной диагностики в основной сессии —
2 итерации; дальше — BUG-NNN в конвейер (см. скилл pm-release-tail-decomposition).
