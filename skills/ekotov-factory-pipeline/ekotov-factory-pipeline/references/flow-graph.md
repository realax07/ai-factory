# Граф флоу: изменения ядра

- Решения Заказчика о расширении графа — отдельный decisions-файл + аддитивная Stage в STAGE_TABLE (scripts/flow_transition.py) СИНХРОННО в обоих репо: эталон ai-factory своим PR-процессом, проектная копия тем же патчем (git diff эталона по файлу применяется git apply). Тест-обновления включать в коммит ядра (122 passed на фабрике).
- 2026-10-07-code-review-flow2: во Флоу 2 (bug_fix) стадия code_review между bug_fix и accept_review. Пробел был: accept_review требует уже существующий approve (замкнутый круг) — ретроспективные ревью багфиксов были невозможны. Ретро-ревью багфикса: ворота flow2 task=2 action=code_review path=code-reviews/BUG-NNN/review-001.md, approval_ref = decision о расширении ядра.
- Ретроспективное ревью закрытых задач пакета: code_review по task N DENY (INVALID_GATE «повторный проход»). Легальный путь — ревью под flow1 task, которая еще открыта, или после расширения ядра.
- Порядок приемки ревью-делегации: платформенный id в Reviewer-Delegation ДО первого finish (finish с метой TBD = blocked, повторный finish по completed-сессии невозможен); sed по строке с markdown-жирностью не срабатывает — правь python-заменой точного текста и сверяй grep'ом. Файл ревью коммитится в ветку → PR → merge; finish с --report на этот файл.
- Если рабочая ветка делегации уже существует, НЕ создавай свою ветку поверх — checkout чужой ветки перетащит твой коммит в ее PR-маршрут; разнос: cherry-pick своего коммита на чистую ветку от main + git reset --hard чужой ветки на ее коммит.
- CI e2e может залипнуть на install-step (CDN) на 30+ мин — не жди, ретриггер пустым коммитом (проверь, что push реально ушел: git push без upstream молчит при ошибке).
