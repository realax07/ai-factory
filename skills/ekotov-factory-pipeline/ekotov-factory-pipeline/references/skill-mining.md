# Майнинг внешних скиллов: procedure адаптации практик из чужих репозиториев

Когда Заказчик говорит «посмотри репозиторий, пройдись по скиллам/агентам» — это класс
задачи с зафиксированной procedure; ниже — проверенные шаги и жесткие требования
Заказчика к результату.

## Procedure

1. Клон во временную папку; security-скан перед чтением (переносить только тексты
   инструкций; чужие скрипты не исполнять без прогона на fixture-входе).
2. Читать папку ЦЕЛИКОМ: scripts/, references/, assets/, hooks/, агентов — не только
   SKILL.md. Заказчик проверяет этот пункт контропросом («ты питон-файлы смотрел или
   опять только skill.md?») — проходка с описанием только по SKILL.md возвращается на
   переделку.
3. Каждого кандидата верифицируй прогоном на НАШЕМ коде до решения: анализатор — на
   реальном модуле проекта, генератор — на fixture-входе. Замеряй долю false positives;
   шумный детектор = отсеять с числом в обосновании, а не «не подошел».
4. Вердикт по каждому: ADOPT / ADOPT-идея-не-код (методика ценнее скрипта) / SKIP с
   основанием. Список отсеянного с причинами — в отчет и коммит: решение «почему нет»
   переиспользуется при следующей проходке.

## Формат принятого скилла (жесткое требование Заказчика)

- SKILL.md (инструкции) + scripts/ (исполняемые инструменты) + references/ (справочники).
  Скилл без скрипта допустим только там, где инструмента объективно не существует; где
  инструмент возможен, Заказчик возвращается вопросом «а скрипты доделал?» — не оставляй
  хвост.
- Каждый скрипт: smoke-прогон до коммита + инструкция вызова в SKILL.md (команды,
  exit-коды, правила интерпретации результатов).
- Python-примеры из SKILL.md валидируй ast-парсом до коммита.

## Регистрация нового скилла — 4 места, все обязательны

1. `SKILL_DIRS` в scripts/factory_init.py — иначе не уедет в новые проекты.
2. Таблица «Скиллы» в agents/<role>_agent.md — чей скилл, там и строка.
3. skills/README.md.
4. Зеркало в проектный репозиторий (skills/) — диффом, не файлом.

После изменений фабрики обновляй README.md/AGENTS.md тем же PR — Заказчик просит это
каждый раз, не жди просьбы.

## Что брать, что нет

- Бери методики и чек-листы (правила ревью, таксономии, матрицы решений) — они
  переиспользуемы; доменные шаблоны чужого стека и интеграции чужих сервисов — нет.
- Инструкции адаптируй под наш стек (примеры — в python, коды ошибок — под наши
  фреймворки); авторство и лицензию источника фиксируй в frontmatter скилла.
