# Параллельные dev-волны в общем дереве: сверяй ветку перед коммитом

Несколько делегаций одного пакета без worktrees работают по очереди в общем
дереве и ПЕРЕКЛЮЧАЮТ ветку под собой. Сабагент, начавший работу на своей
ветке, к моменту коммита может обнаружить ЧУЖУЮ checkout-ветку: `git commit`
молча ляжет на чужую ветку (кейс: p12 волна 2.1 — коммит ушел на
feature/p12-23 при моей feature/p12-21).

Связанное в SKILL.md: --pm-resume (finish blocked-сессии после
конфигурационного gate ERROR), reconcile зависшей зоны, расширение зоны
живой сессии.
Протокол:
- Перед КАЖДЫМ add/commit — `git branch --show-current`.
- Если ветка чужая и рабочее дерево чистое — коммитить НЕЛЬЗЯ: зафиксировать
  дифф (stash/патч-файл) и доложить ПМ; постоянный путь — worktrees
  (session_worktree.sh, процедура ПМ).
- Восстановление, если коммит уже лег на чужую ветку: `git branch -f <моя> <sha>`;
  на чужой ветке (она checkout) — `git reset --hard <ее прежний HEAD>` только
  после проверки отсутствия чужих незакоммиченных правок; затем checkout своей.
- `git branch -f` безопасен только для веток, НЕ checkout в текущем дереве.
- Восстановление УДАЛЕННОЙ ветки — из reflog (`git reflog`, `git fsck
  --lost-found`) без потерь; но это уже ЧЕТВЕРТЫЙ инцидент одного класса:
  общий checkout при параллельных волнах ломает и ветки, и приемки.
- **Коммит ПМ поверх чужой незакоммиченной правки — тот же класс**: `git add
  <свой-файл>` в общем дереве захватывает и измененные ЧУЖИЕ файлы, лежащие в
  дереве (fix-коммит микрофикса унес дельту comments.py параллельной волны в
  main). Перед коммитом ПМ в общем дереве — `git status --porcelain` и сверка
  КАЖДОЙ строки со своей зоной; чужие модификации = сначала изолировать их
  (владелец коммитит в свою ветку), потом коммитить. Последствия не всегда
  вредны (дельта была идентична будущему PR — diff=0), но формально чужой
  контент попал в main мимо своего PR и приемки.
- **Правки волны без коммита гибнут при следующем checkout** — ТЗ каждой волны
  обязано требовать коммит в СВОЮ ветку ДО отчета; субагент, закончивший «в
  рабочем дереве», оставляет правки, которые теряются при следующем переключении.
  Восстановление: `git diff <main> -- <файлы волны> > патч` (ДО любого reset),
  checkout ветки волны, `git apply патч`, гейты (py_compile/node --check),
  коммит ПМ с пометкой «правки восстановлены из worktree». `git reset --hard`
  без предварительно снятого патча теряет содержимое безвозвратно.
- **Приемка (flowctl finish) на общем дереве — источник OUT_OF_ZONE-returned**:
  session_check видит пути base_sha..HEAD ПЛЮС незакоммиченные правки дерева;
  пока параллельная волна держит свои правки, finish дает честный OUT_OF_ZONE
  по чужим путям. Вердикт returned при gates PASS и чистом СОБСТВЕННОМ диффе =
  приемка по существу пройдена; формально закрывается на чистом дереве (после
  сдачи соседней волны), не «чинится» снятием [x].
- **Ветку от main создавай проверив checkout**: sync/ops-ветка, растущая из
  dev-ветки волны, уносит ее коммиты в main мимо QA-порядка (change-PR
  оказывается merged при несобранном QA-контуре). Перед `git checkout -b` —
  `git branch --show-current`; расти ветку ровно от `origin/main`.
- **Конфликт ребейза перекрывающихся волн резолви проверкой «надмножество», не склейкой**:
  когда ревьюер предписал «X мержить первым, из Y дубли выбросить», а ребейз Y на новый
  main конфликтует в общем файле, сравни общие функции обеих версий (git show + difflib
  по функциональным блокам): если версия поздней волны содержит общий код идентично, а
  отличия — только ее собственные блоки, бери ее версию ЦЕЛИКОМ (git show <ветка>:<файл>
  > файл + git add) — ручная склейка возвращает те дубли, которые ревьюер велел устранить.
  После резолюции — node --check каждого тронутого JS до rebase --continue.
- **Коммит сабагента, зависший на ЛОКАЛЬНОМ main (мимо PR)**: не переписывай и не ребейзи —
  забери в PR-маршрут веткой от того же SHA (git branch pipeline/<slug> <sha> + push + PR).
  Основное дерево при этом может быть занято живой делегацией (checkout переключен на ее
  ветку) — ПМ-правки (чекбоксы, mapping) делай во ВТОРОМ worktree от origin/main
  (git worktree add /tmp/<slug> origin/main), не переключая дерево делегации.
- СТАНД: изоляция worktree на волну (session_worktree.sh) — не героика с
  ветками в общем дереве. Цена общего дерева за один вечер — 4 инцидента
  (ветка+потерянные правки+чужой файл в коммите+race) и 3 испорченные приемки.

## flowctl: finish/reconcile на волнах

- **--pm-mode обязателен на finish**: без `--pm-mode commits --pm-commits <sha>`
  обязательный pm_bounds_check дает ERROR «режим не задан» → blocked. ЗАТВЫШ:
  повторный finish с правильными флагами НЕ снимает blocked — сессия уже в
  статусе blocked, finish возвращает старый вердикт идемпотентно, ворота не
  перезапускаются. Восстановление: тот же finish + `--pm-resume` — переводит
  blocked→running (запись в lifecycle) и гонит ворота заново; принимается только
  если все дефекты записи — gate ERROR/SKIPPED (ошибка конфигурации запускающего);
  gate FAIL и ZONE_* resume не проходит.
- **Отчет finish должен существовать на диске**: если dev-волна не положила
  REPORT в репо (вне своей зоны), запиши резюме приемки ПМ в файл
  (`~/.hermes/state/reports/<corr>-dev-report.md`) и передай путь — finish без
  файла отклоняется ДО ворот («агентский отчет не найден»), и этот отказ тоже
  ставит blocked (см. выше).
- **ZONE_CONFLICT на prepare от ЗАВЕРШЕННОЙ сессии снимай reconcile'ом**:
  finished-сессия держит резервацию зоны; prepare с пересекающимися путями
  отклоняется. `flowctl.py reconcile --delegation-id deleg-<id> --repo <repo>`
  переводит finished→stale, после чего prepare проходит. Прогоняй reconcile по
  id предыдущей волны перед prepare следующей — паттерн на каждую волну.
- **Отчет dev-делегации вне зоны записи**: если REPORT некуда класть в репо по
  зоне, сними патч-дифф и коммит-хеш волны в файл отчета — финиш по нему честен.
- **Ревью хвостов волны при приемке — сначала определяй владельца**: правки в
  рабочем дереве на момент finish могут принадлежать соседней волне (ее файлы
  вне твоей зоны) или уже быть закоммичены в ее ветку. Сверяй `git diff <main>
  -- <файл>` против ветки владельца: diff=0 — это уже ее контент, не дублируй;
  diff>0 — незакоммиченный хвост, требуй коммита владельцем до своей приемки.

## CSS-миксфиксы вне пакета: короткий маршрут

Срочный UI-фикс от Заказчика между волнами (кейс: footer сайдбара пропадал на
галерее при длинной сетке — сайдбар-флекс не был прижат к viewport) — маршрут:
1. Воспроизведи изолированным стендом (минимальный HTML-каркас + реальные CSS
   из репо через локальный http.server; element-замеры через playwright:
   getBoundingClientRect футера против window.innerHeight) — без стенда «чинь
   на глаз» запрещено: правка layout-а без воспроизведения ломает соседние
   страницы молча.
2. Фикс — минимальный CSS в существующем файле стилей (для layout-прилипания:
   `position: sticky; top: 0; height: 100vh; overflow-y: auto` + парный
   внутренний скролл контента), с комментарием в CSS: что ломалось и почему.
3. Верификация на ТОМ ЖЕ стенде (фикс-инъекция снята — реальный файл) + скролл
   колесом + вторая короткая страница (регресс на коротком контенте).
4. Маркер PR `[chore]` (вне пакета — change-маркер требует QA-комплект, которого
   нет); мерж обычным путем; на прод попадает со следующим релизом (бамп
   static_v обязателен — любая правка статики без бампа не доедет до браузера).
5. UI-фикс, найденный Заказчиком вручную, — проверь СМЕЖНЫЕ страницы тем же
   стендом (сайдбар общий для всех разделов: починка на галерее могла сломать
   борду/настройки — прогони каркас каждой).

## Цена общего дерева: flowctl-приемки

Общее дерево ломает не только ветки, но и ворота finish:

- **OUT_OF_ZONE на приемке волны** — session_check берет пути
  `base_sha..HEAD` ПЛЮС незакоммиченные правки дерева. Пока чужая волна
  держит в дереве свои правки (или чужой коммит вошел в диапазон
  base..HEAD через merge), finish волны дает честный OUT_OF_ZONE по чужим
  путям. Вердикт returned при gates PASS и чистом СОБСТВЕННОМ диффе =
  приемка по существу пройдена; формально закрывается на чистом дереве
  (после сдачи параллельной волны), не «чинится» снятием [x].
- **Попадание волны в main мимо QA-порядка**: sync/ops-ветка, растущая из
  dev-ветки волны, уносит ее коммиты в main merge'ем PR'аsync-задачи —
  change-PR оказывается «merged», хотя QA-контур еще не собран. Перед
  созданием ЛЮБОЙ ветки от main проверь `git branch --show-current` и
  расти ветку ровно от `origin/main`, не от чекаута.
- СТАНДАРТ: изоляция worktree на волну (session_worktree.sh) — не героика
  с ветками в общем дереве. Стоимость одного общего дерева за вечер —
  4 инцидента + 3 испорченные приемки.
