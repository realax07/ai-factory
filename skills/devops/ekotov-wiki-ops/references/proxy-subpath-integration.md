# Проксирование внешнего статического приложения через подпуть nginx (паттерн game-portal)

Внешнее приложение (свой Node/статический сервер), поднятое отдельным контейнером на сети ekotov, отдается через подпуть основного nginx с существующим TLS. Проверенный рецепт — P26 game-portal (сайдбар «Игры» → /games/).

## Контейнер приложения

- Standalone вне compose-матрицы: `docker run -d --name <name> --restart unless-stopped --network ekotov-wiki-par_default -v <репо>:/srv:ro -w /srv -e HOST=0.0.0.0 <образ> <старт-команда>`.
- Внутри контейнера bind 0.0.0.0 безопасен (порт НЕ публикуется наружу) — nginx соседней сети достает по имени контейнера. Внутренний код, хардкодящий 127.0.0.1, требует локального патча HOST-env (коммитить локально, не пушить) — и этот же флаг ОБЯЗАТЕЛЬНО отражать в RUNBOOK-команде запуска, иначе вечный 502 (ECONNREFUSED на upstream).
- Названный том (кэш/данные) — chown uid сервиса ДО первого up; маунтпоинт НЕ внутрь существующего ro-маунта.

## nginx: четыре поверхности абсолютных путей — проверь ВСЕ

Приложение под подпутью ломается на абсолютных путях в ЧЕТЫРЕХ разных местах; ревью обязано назвать каждое:

1. **HTML (href/src="/")** — sub_filter `href="/` → `href="/<prefix>/`, то же для src, sub_filter_types text/html, once off.
2. **JS-фетчи (fetch("/api/…"))** — sub_filter_types ОБЯЗАТЕЛЬНО text/javascript (не только application/javascript: реальные серверы отдают .js как text/javascript — расхождение = мертвый фетч при зеленом nginx -t).
3. **JSON-полезные нагрузки** (каталог с путями к превью/ассетам) — sub_filter_types application/json + правило с якорем-кавычкой (`"/previews/` → `"/<prefix>/previews/`), чтобы не задеть легитимные пути, уже несущие префикс (url:"/<prefix>/<id>/").
4. **Нативная маршрутизация приложения, совпадающая с префиксом** — если app роутит `/games/<id>/` сам, прокси со СРЕЗОМ префикса отдаст бэкенду `/id/` → 404. Лечение: regex-location для страниц/дистрибутивов БЕЗ вырезания (proxy_pass без URI), и перевод основного strip-префикса из `^~` в обычный prefix (иначе ^~ глотает regex: порядок nginx exact > ^~ > regex > prefix).

Плюс: X-Frame-Options для локации приложения — SAMEORIGIN, если приложение само фреймит свой контент (DENY убивает его собственный iframe-плеер); известный обходной класс — e2e на одноразовом docker-стенде (nginx:alpine с полным конфигом ‖ реальный контейнер приложения), а не только nginx -t: синтаксис зелен при мертвом фетче.

## Чек-лист приемки прокси

- Корень подпути 200 + sub_filter переписал href/src (grep тела).
- JS-фетч переписан (grep тела .js на /<prefix>/api).
- JSON-поля с путями переписаны, легитимные префиксованные пути не задвоены (grep "<prefix>/<prefix>/" = 0).
- Страницы приложения (нативные маршруты) 200, их относительные ассеты 200.
- Негатив: несуществующий маршрут — собственный 404 приложения (не 502 nginx).
- Заголовки: X-Frame-Options соответствует iframe-модели приложения.
- На проде после деплоя: v=<тег> в HTML, новый location живой, ассеты 200.

## Локальный репо-патч приложения

Минимальный патч чужого кода для развертывания (HOST-env) коммитится ЛОКАЛЬНО (не пушится в апстрим) и документируется в RUNBOOK рядом с командой запуска — иначе следующий перезапуск контейнера вернет старое поведение молча.
