# Добавление второго участника в живой Telegram-гейтвей

Процедура для этого VPS (gateway обслуживает основной чат Заказчика). Официальная база — docs `/user-guide/messaging`; здесь — фактический путь на этой машине.

## Доступ (allowlist / pairing)

По умолчанию гейтвей отклоняет всех не из allowlist. Два пути:

- **Явный ID**: добавить ID в `.env` строку `TELEGRAM_ALLOWED_USERS=<id1>,<id2>` (запятая, без пробелов; править только эту строку — файл несет секреты). Требует перезапуска гейтвея.
- **Pairing (проще, ID не нужен)**: человек пишет боту → получает one-time код → `hermes pairing approve telegram <КОД>`.

## Роль через channel_overrides

Пер-чатовый системный промпт (заменяет глобальный ТОЛЬКО в этом чате) — через CLI, не руками в config.yaml:

```bash
hermes config set platforms.telegram.channel_overrides.<chat_id>.system_prompt '<роль и границы>'
```

Промпт обязан задавать: роль, зону (какой проект), границы (что вне зоны → к Заказчику), и правило «инфраструктурой не командовать». Это SOFT-граница: набор инструментов у агента общий, железного разделения нет — исполняющие действия (деплой, прод) все равно идут через ПМ.

## Рестарт: ТОЛЬКО из внешней оболочки

`hermes gateway restart` из терминала агента ЗАБЛОКИРОВАН гвардом: терминал агента — процесс-потомок гейтвея, SIGTERM убивает и его (собственная сессия умирает на середине хода). Команду выполняет Заказчик в SSH-консоли VPS. После рестарта наш чат переподключается автоматически; `restart_notification` шлет уведомление в home-канал.

## Порядок и верификация

1. `.env` allowlist + `hermes config set` override.
2. Заказчик: `hermes gateway restart` в SSH (проверка факта рестарта: PID процесса `gateway run` сменился, в `~/.hermes/logs/gateway.log` свежая строка «control socket listening»).
3. Участник пишет боту → в `gateway.log` появляется `inbound message: platform=telegram user=... chat=...` — входящие от его ID больше не DENY.
4. Home-канал не трогать: home остается чатом Заказчика (участник не получает home-доставку кронов).

## Исходящее к участнику

`hermes send -t telegram:<chat_id> '<текст>'` — работает без рестарта и без allowlist ( outbound — только inbound фильтруется). Удобно для представления/инструкций до первого сообщения участника.
